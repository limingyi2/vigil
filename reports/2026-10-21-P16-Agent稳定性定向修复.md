分支 `codex/fix-agent-image-tool-diagnostics-20261022`，基点 `b7e5321`（dev）。
本文只记录**有代码或台账证据**的结论；没跑过的写在「未测」里，不并进「已修复」。

---

## 一、根因

### P0-A 流式聊天丢图

`/api/chat/stream` 拿 `body` 时把 `img` 当成了工具调用凭证一类的东西，**建 Agent run 时明确排除**了带图请求
（`not body.get('img')` 才允许成 run），同时这条通道根本没人解码 `img`，于是图片在入口就蒸发了：
模型侧只收到文字，用户侧看到"她照着图回答了"，实际她一个字都没看到。四个状态（收到 / 上传 / 看懂 / 回复）
在事件流里也压成了一个，看着像"图没发出去"。

### P0-B MiMo 报"工具名称、参数或调用标识无效"

真实台账里三条记录指向同一处：`invalid_tool`，`detail = "Expecting value: line 1 column 10 (char 9)"`，
`invalid_attempts = 3`、`xml_fallback = 3`。

`brain/model_providers/execution.py` 合并流式片段时，对 `id` / `name` / `type` 一视同仁地 `+=` 盲拼。
相当一部分网关（含 MiMo 网关）每帧都重发完整标识，于是 `read_file` 被拼成 `read_fileread_file`，
`call_abc` 被拼成 `call_abccall_abc`；标识一变形，后续 arguments 就配不上对，解析到一半炸成
`Expecting value`。**模型发的是合法调用，是我们自己拼坏的。**

### P0-C 错误详情到不了用户眼前

`_tool()` 把异常当场吞成 `tool_unknown`，`error` 只写进内存变量而不落 step；`localtools` 的收据只有
`state` 没有 `reason`；前端拿到的 error 是字符串，只能原样打出来。结果：用户看到"失败"，
不知道是"客户端没连上"、"你没点同意"，还是"参数不合法"。

### P0-D 她不理解上一轮为什么失败

台账里写得清清楚楚（`not_dispatched` + reason），但新任务启动时一个字都不带过去。
模型拿不到证据，只能猜，猜出来最常见的一种就是"用户拒绝了审批"——而这句假话会写进回答。

### P1-E 工作区检索

工作区路径只在提示词里出现过，工具真正执行时用的是另一套默认值；越权访问的拒绝理由也没分场景。

### P1-F 无法中途改主意

执行中发消息只有"再来一轮"这一条路：旧 run 不知道被接管，要么继续调度，要么直接判死。

## 二、改了什么

### `brain/model_providers/execution.py`（+35 / -?）

新增 `merge_identifier(current, fragment)`：`fragment == current`、`current.startswith(fragment)`、
`fragment.startswith(current)` 三种情况都收敛成一个，只有真分片才拼接。
`completion_events` 里原来对 `target[key] += value` 一刀切，现在**只有 `arguments` 走拼接**，
`id` / `name` 走 `merge_identifier`；`type` 的校验从"必须等于 `function`"放宽为
`not in ('function', None)` 才拒——`None` 是网关常见省略，不该判非法。

### `brain/agent_runs.py`（+328）

| 位置 | 内容 |
|---|---|
| `_call_id(cid, index, used)` | 标识清洗：只去空白/引号；空则生成 `call_%d_%s`；同批重复加 `_n` 后缀；超 128 截断。**不再因为标识形状可疑就拒掉整批** |
| `_calls()` | 批次仍保持原子拒绝（半批派发比整批拒更危险），但报错改成「调用序号 + 工具名 + 具体缺陷 + 收到的前 160 字」 |
| invalid_tool 分支 | 原来 `raw` 是死变量。现在落盘到 `item['last_invalid']`、`model_step['error']`、`model_step['invalid_calls']`，重试提示保留"无法解析 / 未通过校验"双措辞并带 300 字 detail |
| `_SECRET_SHAPES` + `_redact_error_text()` | `sk-/rk-/pk-/ghp-/xox-/AKIA/LTAI` 前缀、`Bearer`、全大写下划线变量名、32+ 位 hex；截断 400 字 |
| `_TOOL_ERROR_MAP` + `_tool_error()` | reason → `(category, hint, was_dispatched)`。`dispatched` 不靠猜：`approval_denied` 这种"状态看着像没发生、实际客户端已认领"的显式标 `True` |
| `_tool()` | 异常不再吞成 `tool_unknown`，保留异常类型与消息（经脱敏）；`step['error']` 真正写进去；修掉「空结果一律覆盖 reason」的 bug → `if not reason: reason = 'tool_unknown'` |
| `failure_brief(owner, exclude, now)` | 只读台账，回最近 24h 内最多 2 条失败摘要（Run ID / 工具 / 状态 / 原因 / 有无可验证回执）。块首固定声明"这是台账记录、不是推测；无法确定就说无法确定；**重试不是许可**" |

### `brain/localtools.py`（+38）

`call()` 内新增 `fail(state, reason, detail)` 闭包，每个失败分支都补齐 `reason`：
`cancelled` / `unknown_tool` / `permission_denied` / `client_offline` / `client_busy` /
`cancelled_in_flight` / `timeout_after_dispatch` / `approval_denied` / `tool_failed` / `empty_output`。
**收据从"成功/失败"两态变成"失败且知道为什么"九态。**

### `brain/server.py`（+189）

- `IMAGE_MAX_BYTES = 8MB`、`_decode_turn_image()`：`re.fullmatch(r'[A-Za-z0-9+/=\s]+')` 前置校验，
  分 `empty` / `not_base64` / `too_large` 三种拒绝理由。
- `_describe_turn_image()`：内容哈希 + 1h TTL，缓存上限 32 条 → **同一张图不重复调视觉**。
- `_image_note(desc, rejected)`：三种话术——「（他发的图：…）」/「（他发了张图片，没看清）」/「（…没看到内容）」。
  视觉不可用时**明说看不到，禁止假装**。
- `/api/chat/stream`：图片处理挪到 Agent 判定**之前**；发两条 `image` 事件区分 receive / describe 两个阶段；
  移除 `not body.get('img')` 排除条件，带图请求照样能进 Agent run；`_display.stream()` 用 `_disp_text` 存原文，
  不把"（他发的图：描述）"当用户原话写进历史。
- `/api/chat`（非流式）：进模型前同样校验，非法图直接 400。
- `_new_agent_run`：注入 `agent_runs.failure_brief(...)`。
- 新增 `POST /api/agent/runs/<rid>/interject`；`/api/chat/stream` 支持 `interject_of`，
  **排在 `resume_of` 之前且与之 elif 互斥**（同 request_id 会被建 run 报指纹冲突）。

### 前端

- `client/src/js/agent-view.js`：`ERROR_LABEL` 九类中文名 + `errorInfo(meta)` + `redact()` 强化。
  步骤行**常显**徽标（按 category 上色）和一句"为什么"，展开区放"诊断（分类 / 是否已派发 / 原因）"与"执行凭据"。
  兼容旧的字符串形态 error。
- `client/src/js/pages.js`：`image` 事件分支（"图片已看懂，正在回复" / "视觉模型不可用（…），她看不到这张图"）；
  `pendingInterjectOf` + `chatPayload.interject_of`；`busy` 不再是发送的唯一阻断条件。
- `client/src/chat.css`：`.agent-step-badge` / `.agent-step-why`。

### 测试（新增 6 个文件，69 例）

`tests/test_p16_tool_protocol.py`（17）、`test_p16_tool_error_detail.py`（21）、
`test_p16_stream_image.py`（13）、`test_p16_failure_brief.py`（8）、
