## 一、修复内容（按 D1 → D2 → D3 优先级）

### D1：Planner/ReAct 委派分发统一（必修）
- `brain/tools.py` `run_tool()`：`delegate_to_local` 统一路由到
  `delegation/bridge.py` 的 `delegate_from_text()`，与 FC 入口
  `invoke_spec()` → `delegate_to_local()` 走**同一道门**
  （enabled 门控 → 合同校验 → Dispatcher → 证据渲染）。
  修复前 Planner 执行委派返回 `None`（工具表无此名）。
- `brain/planner.py` `execute_plan()`：委派步骤把步骤描述并入 arg，
  路由才能从自由文本里识别授权工作区；其他工具行为不变。
- `brain/delegation/router.py` 新增 `kind_for_goal()`：Planner 字符串
  入口确定性推断合同 kind（白名单内，拿不准回落 file_discovery）。
- 回归测试：`tests/test_delegation.py` `TestD1PlannerDispatch`
  （cloud 返回 None / 无授权路径返回 None / 授权根内执行并回传
  verified / 失败错误类别透传）。

### D2：PC 在线授权路径走 local_file_*（路由逻辑，非提示词）
- `brain/localtools.py` 新增 `pc_online()`：以客户端 1.5s 轮询的
  `_LAST_POLL`（60s 新鲜期）为"local_file_* 此刻可不可用"的事实来源。
- `brain/delegation/bridge.py` 新增**请求级路由锁**
  （`lock_delegation()` / `delegation_locked()`，ContextVar 线程隔离）。
- `brain/server.py`：每轮聊天先复位锁；PC 在线且本轮绝对路径
  **不在**委派沙箱授权根（`delegation.allowed_roots`）时上锁并跳过
  Planner 直走 FC。上锁后：
  - `tools.all_specs()` **整项摘除** delegate_to_local（模型选不到，
    不是改描述劝退）；
  - `invoke_spec()` / `run_tool()` 执行层硬拒改道（防 XML 文本兜底
    绕过工具表），一个委派都不发。
- FC 合同校验对"沙箱授权根外 + PC 在线"仍返回 local_file_* 改道提示；
  授权根校验、客户端白名单两道安全边界均未改动。
- 回归测试：`TestD2PCRouting` 新增 3 个路由锁用例（工具表摘除 /
  FC 硬拒且零委派 / Planner 入口返回 None）。

### D3：保留原始响应、有限修复、不空转
- `brain/delegation/dispatcher.py`：
  - 新增零模型、机械、语义无损的 `_repair_json_text()`（剥代码围栏 /
    截首个 JSON 对象 / 去尾逗号），修复文本仍须过**完整验收**；
  - 委派记录新增 `last_raw`（截断 600 字落盘）、`json_raw_ok` /
    `json_repaired` / `json_repair` / `retry_problems` 字段；
  - 模型级修正仍**只允许一次**，不提高任何预算；
  - 新增：Ollama think 模型偶发**空壳响应**（content/tool_calls 全空，
    provider 抛 bad_response）时，在现有请求预算内续跑**最多一次**；
    连不上/超时/OOM 仍立即失败，绝不提权云端。
- 回归测试：空壳响应续跑成功、连续两次空响应即失败且仅 2 次请求。
