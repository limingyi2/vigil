# Vigil 本地知识库接入验证

验证日期：2026-10-11。范围：本地知识库模块、插件工具接线及本机模型实际调用。

## 存储位置与搭建入口

| 内容 | 位置 |
|---|---|
| Agent 工具与 HTTP 接口 | [`brain/plugins/kb.py`](../brain/plugins/kb.py) |
| 导入、检索与分区 | [`brain/kb/engine.py`](../brain/kb/engine.py) |
| 配置合并 | [`brain/kb/config.py`](../brain/kb/config.py) |
| 源码运行时的库 | `brain/data/kb/` |
| 打包运行时的库 | 本地 Brain 可执行文件旁的 `data/kb/` |
| 测试或多实例 | `VIGIL_HOME/data/kb/`，按运行目录定位 |
| 搭建说明 | [`docs/archive/本地知识库.md`](../docs/archive/本地知识库.md) |

`data/kb/` 保存索引和文档块，并非自动监控的资料投递目录。需要通过客户端知识库页面或 `/api/plugin/kb/ingest` 导入。资料按人设和渠道分区，查询分区必须与导入分区一致。

当前源码运行目录的检查结果：`brain/data/kb/settings.json` 中 `enabled=false`、`inject=false`，默认分区块数为 0。因此现状是知识库停用且默认库为空；本次没有更改该运行设置。其他打包实例或渠道分区的实际状态需要分别检查。

## 验证设计

先运行 `tests/test_kb.py` 的模块回归，再通过真实 Brain 原生工具循环调用本机 `qwen27b-efficientthink:latest`。模型仅能使用真实插件生成的 `kb_search` schema，执行经现有工具分发进入知识库实现。

测试在独立临时 `VIGIL_HOME` 中构造一份合成维修记录，自动注入关闭，验收码临时随机生成。模型必须调用工具才能获得验收码。第二个场景清空隔离库，检查是否明确报告没有资料。

嵌入向量采用确定性受控值，知识库存储、插件 schema、工具分发、Brain 循环及模型回答均实际执行。该方法用于验证接线与答案依据，不评价真实 embedding 的语义排序质量；相关度 1.00 仅属于受控 fixture。

## 验证结果

| 项目 | 结果 | 证据 |
|---|---|---|
| 知识库模块回归 | 28 项通过 | 切块、存储、分区、检索与插件契约 |
| 工具发现 | 通过 | 工具表包含 `kb_search` |
| 有资料场景 | 通过 | 调用 `kb_search`，返回随机验收码，并引用 `maintenance-test.md` |
| 空库场景 | 通过 | 调用 `kb_search` 后明确报告未找到资料，没有沿用上一场景的验收码 |
| 配置保护 | 通过 | 本机知识库设置文件的前后 SHA-256 相同 |

两条真实本机模型任务共 4 次模型请求、3 次工具调用，耗时 9.781 秒。Brain 记录两条任务合计输入 3,184、输出 211 tokens；逐次 HTTP 响应的 `usage` 字段未提供数值，因此 token 采用 Brain 汇总统计，并保留这一口径区别。

结果见 [本地知识库验证结果.json](本地知识库验证结果.json)，验证脚本见 [check_local_kb.py](scripts/check_local_kb.py)。试验未读取生产资料、未调用付费模型 API，临时知识库在验证结束后移除。

执行版本为当前工作区，包含尚未提交的本地模型提供者改动；结果文件附 Git 基线和归档时相关源码 SHA-256。单凭仓库基线 commit 不能完全复现这次运行，本报告不将这些运行结果归于未包含对应源码的已发布版本。

## 接入判断

本机模型能发现并调用知识库工具，也能根据检索结果引用文档；但当前默认运行库停用且没有资料，所以日常对话不能据此直接查到内容。实际启用需选择合适的嵌入后端、开启库、导入资料，并在正确的渠道分区验证命中。自动注入可以单独关闭，保留按需工具查询。
