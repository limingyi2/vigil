# 插件前端注入（完全插入即用）方案

> 历史设计稿。P21 规则已取代文中的 `brain/plugins/` 自动加载假设：可选插件必须由用户明确安装到 `data/installed_plugins/`，客户端不打包源码目录里的插件。不要按本文“丢入源码目录自动生效”的描述操作。

> 版本：v1.0 · 2026-10-10
> 状态：待实施
> 详细实现要点见 `docs/01-待办清单.md`

---

## 一、要解决什么问题

### 现状
- Vigil 的插件系统只能加**后端逻辑**（钩子、工具、路由）
- 想加前端功能（新页面、自定义主题、壁纸背景、UI 扩展）必须手动改 `pages.js` / `app.js`
- 插件不是"插入即用"——装了后端插件，前端还得手动改代码

### 目标
插件文件夹丢进 `brain/plugins/`，**客户端 10 秒内自动生效**：
- 后端逻辑自动加载（现有能力，不变）
- **前端代码自动注入**（新增）
- **新页面自动出现在导航栏**（新增）
- 插件出错只打日志不崩溃（错误隔离）
- 设置页能按渠道开关（联动现有 features 系统）

类比 DeepSeek Harness 的插件体系：后端插件可以带一段前端代码，加载时自动注入 Web UI。

## 二、整体架构

```
插件目录 brain/plugins/wallpaper/
  ├── __init__.py       后端逻辑（NAME/DESC/ROUTES/TOOL_SPECS/钩子）
  ├── frontend.js       前端代码（可选，注入渲染进程）
  └── frontend.css      前端样式（可选，注入 <style>）
         │
         ▼
后端 plugin_host.py
  ├── 扫描插件目录时同时读 frontend.js / frontend.css
  ├── Plugin 对象新增 frontend_js / frontend_css 字段
  └── 注册路由 GET /api/plugins/frontend → 返回所有插件前端资源 + 版本号
         │
         ▼
Electron 主进程
  ├── preload.js 暴露 window.vigil.runJS(code)
  └── main.js 注册 IPC handler → webContents.executeJavaScript(code)
     （用 executeJavaScript 而不是 <script> 内联，绕过 CSP 的 script-src 'self' 限制）
         │
         ▼
前端 app.js boot()
  ├── 拉 GET /api/plugins/frontend
  ├── 注入 CSS（<style id="plugin-css-<name>">）
  ├── 暴露全局对象：
  │     window.VigilPlugin { registerPage, injectCSS, on, emit }
  │     window.VigilAPI = API（插件复用接口封装）
  │     window.VigilUI = U（插件复用 UI 组件）
  ├── 用 runJS 安全注入每个插件的 frontend.js（独立 try/catch 包裹）
  └── 启动 10 秒轮询：版本号变了自动 location.reload()
         │
         ▼
插件前端代码里
  ├── VigilPlugin.registerPage({id,name,icon,render}) → 导航自动多一项
  ├── VigilAPI.get('/api/plugin/xxx') → 调后端接口（走 IPC，不被 CSP 拦）
  ├── VigilUI.toast('...') → 弹提示
  └── 直接操作 DOM（加背景层、改样式等）
```

## 三、需要改的代码

### 1. 后端：`brain/plugin_host.py`（+~30 行）

| 改动 | 说明 |
|---|---|
| Plugin 类新增字段 | `self.frontend_js = ""`、`self.frontend_css = ""` |
| 读取前端资源 | `__init__` 里从插件同目录读 `frontend.js` / `frontend.css` |
| 新增 `frontend_assets()` 函数 | 返回 `{"version": <时间戳>, "plugins": [{name, js, css, enabled}, ...]}` |
| 只返回有前端资源的插件 | js 或 css 非空才返回 |

### 2. 后端：`brain/server.py`（+~5 行）

- 注册路由 `GET /api/plugins/frontend` → 返回 `plugin_host.frontend_assets()`

### 3. Electron：`client/electron/preload.js`（+~2 行）

- 暴露 `window.vigil.runJS = (code) => ipcRenderer.invoke('run-js', code)`

### 4. Electron：`client/electron/main.js`（+~8 行）

- 注册 `ipcMain.handle('run-js', ...)` → `e.sender.executeJavaScript(code)`
- try/catch 包裹，失败返回 null 不崩溃

### 5. 前端：`client/src/js/app.js`（+~100 行）

| 改动 | 说明 |
|---|---|
| 暴露全局 API | `window.VigilAPI = API; window.VigilUI = U` |
| VigilPlugin 全局对象 | `registerPage()` / `injectCSS()` / 事件总线 `on()` / `emit()` |
| `loadPluginFrontends()` 函数 | 拉接口 → 注入 CSS → 用 runJS 注入 JS（每个独立 try/catch） |
| 热重载轮询 | 10 秒查一次版本号，变了 `location.reload()` |
| 在 `boot()` 里调用 | `buildNav()` 之后、`ping()` 之前调用 `await loadPluginFrontends()` |

### 6. 开关联动（可选优化，+~10 行）

- `/api/plugins/frontend` 返回里每个插件带 `enabled` 字段（走 features 系统）
- 用户在设置页改了插件开关后，`setTimeout(() => location.reload(), 500)`
- 关了的插件刷新后前端代码不注入、页面消失

### 合计：~155 行核心代码

## 四、示例插件：wallpaper（验证整条链路）

### 目录结构
```
brain/plugins/wallpaper/
  ├── __init__.py    后端：声明 NAME/DESC/FEATURE，注册一个测试路由
  ├── frontend.js    前端：加渐变背景层 + 注册「壁纸」设置页 + 调后端接口
  └── frontend.css   样式：让应用背景透明露出壁纸层
```

### 验证点
- 丢进目录后，客户端 10 秒内自动刷新
- 导航栏自动多出「壁纸」一项
- 界面背景出现淡紫色渐变
- 「壁纸」页里后端接口返回正常
- 点按钮能切换背景显隐
- Console 有 `[wallpaper] 前端注入成功` 日志
- 设置页关掉 wallpaper 开关，刷新后背景消失、页面消失

## 五、边界情况与错误处理

| 场景 | 处理方式 |
|---|---|
| 插件前端 JS 报错 | 每个插件独立 try/catch，只在 Console 打红，不影响其他插件和主界面 |
| 插件用了未定义变量 | 被 try/catch 接住，Console 报错；文档写明只能用 VigilPlugin/VigilAPI/VigilUI 三个全局 |
| 后端接口挂了 | `loadPluginFrontends()` 静默 catch，不影响启动；热重载轮询失败也静默，下一轮再试 |
| 插件重复注册页面 | `registerPage()` 检查 `PAGES.find(p => p.id === page.id)`，重复跳过 |
| CSP 限制 | 用 `executeJavaScript` 注入，不受 `script-src 'self'` 限制；插件不能直接 `fetch`（会被 `connect-src` 拦），必须用 `VigilAPI` |
| 单文件插件（无前端） | `frontend_js` / `frontend_css` 为空字符串，不注入，完全向后兼容 |

## 六、安全设计

| 风险 | 防护 |
|---|---|
| 恶意插件前端代码 | 插件只能通过 `VigilAPI` 调后端接口（走 IPC，有 token 校验）；不能直接 `fetch` 外部资源（CSP 拦截） |
| 插件崩溃拖垮主界面 | 每个插件独立 try/catch，错误隔离 |
| 插件篡改其他插件数据 | 插件间通过 `VigilPlugin` 事件总线通信，不直接共享作用域 |
| 未授权插件注入 | 插件必须放在 `brain/plugins/` 目录才能被加载，文件系统权限即授权 |

## 七、部署步骤

1. 改 `plugin_host.py`（加前端资源读取 + `frontend_assets()` 函数）
2. 改 `server.py`（注册 `/api/plugins/frontend` 路由）
3. 改 `preload.js`（暴露 `runJS`）
4. 改 `main.js`（注册 `run-js` IPC handler）
5. 改 `app.js`（暴露全局对象 + VigilPlugin + 加载函数 + 热重载轮询）
6. 重启 brain + 重启客户端

8. 丢 wallpaper 示例插件进目录，10 秒内验证自动注入

## 九、已知限制

1. **热重载是整页刷新**——版本变了直接 `location.reload()`，不是精准 HMR；本地应用刷新零点几秒，可接受
2. **插件前端不能直接 fetch**——必须用 `VigilAPI`（走 IPC），因为 CSP 的 `connect-src` 限制
3. **插件间通信只有简单事件总线**——没有复杂的服务依赖注入（对比 Cordis/DSH 的 ctx 体系），但对当前规模够用
4. **没有插件卸载时的 cleanup 机制**——关插件靠刷新，刷新后旧代码自然消失；如果插件加了全局定时器，刷新也会清掉
5. **前端注入只支持 Electron 客户端**——手机 App / 网页端不支持（这些端没有 runJS 通道）

## 十、与 DSH/Cordis 的对比

| 能力 | Vigil（本方案后） | DSH / Cordis |
|---|---|---|
| 后端插件钩子 | ✅ on_turn_in / prompt / on_reply / start | ✅ 更丰富的生命周期钩子 |
| 工具声明 | ✅ TOOL_SPECS | ✅ ctx 注入 |
| 路由注册 | ✅ ROUTES | ✅ ctx.router |
| 前端代码注入 | ✅（本方案新增） | ✅ |
| 插件间通信 | ⚠️ 简单事件总线 | ✅ ctx 事件系统 + 服务依赖注入 |
| 服务依赖注入 | ❌ | ✅ |
| 卸载自动清理 | ⚠️ 靠刷新 | ✅ ctx.dispose |
| 配置校验 | ❌ | ✅ schema 校验 |
| 适用规模 | 单人维护、10-20 插件 | 大型生态、上百插件 |

**结论**：本方案让 Vigil 的插件体系达到"前后端插入即用"，覆盖 90% 的实际需求。服务依赖注入、配置校验等高级特性对当前单人维护规模来说是过度设计，未来插件多了再考虑。
