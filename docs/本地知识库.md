# 本地知识库（RAG）

让她能翻**你自己的文档**回答问题：把 `.md` / `.txt` / `.pdf` / 代码文件丢进来，
切块、向量化、存本地；她聊天时自动检索相关段落，也能自己调 `kb_search` 去查。

```
brain/kb/                    框架本体
  config.py                  所有可调项（两处真源：config.json 的 kb 段 + data/kb/settings.json）
  chunker.py                 切块：先按标题分节，节内按段累加，超长才硬切
  reader.py                  读文件成文本（.md/.txt/代码/.pdf）
  embedder.py                嵌入：api / local / fastembed 三条后端
  store.py                   落盘：chunks.json + vectors.npy + meta.json（无向量库依赖）
  engine.py                  门面：摄入、检索、统计、分区
  selftest.py                真嵌入自测：python -m kb.selftest
  kb_core.py / ingest.py / search.py   早期原型（CLI，路径写死在 D 盘，保留可用）
brain/plugins/kb.py          接线：工具 + 每轮注入 + /api/plugin/kb/*
tests/test_kb.py             28 项单测（假向量，不联网）
```

---

## 一、它和「记忆」不是一回事

| | 记忆（memory_store_v2） | 知识库（kb） |
|---|---|---|
| 内容 | 她跟你聊天时攒下来的事 | 你主动导入的文档 |
| 谁写的 | 她自动提取 | 你导入 / 删除 |
| 分区 | 人设 × 渠道 | 人设 × 渠道（同一套规则） |
| 注入 | 每轮 | 每轮（命中才注入） |
| 工具 | 无（她不用调） | `kb_search`（她能主动查） |

分开的理由：记忆是"她记得你"，知识库是"她查得到资料"。
混在一起会出现"她把文档原文当成你告诉过她的事"。

---

## 二、装什么、放哪

**不需要装任何新东西。** 默认嵌入后端复用记忆库那条路
（`memory_store_v2.embed_texts`：云端 OpenAI 兼容 `/embeddings`，bge-m3，1024 维；
失败自动降级到本地 fastembed 的 bge-small-zh-v1.5）。numpy 早就在依赖里。

数据落盘（按人设 × 渠道分区）：

```
brain/data/kb/
  default/            默认人设 + App
  wechat/             默认人设 + 微信
  <人设key>.app/      其他 人设 × 渠道
    chunks.json       块正本
    vectors.npy       向量矩阵（行序与 chunks.json 严格对齐）
    ids.json          稳定 id（md5(来源:块号)，重跑不会重复入库）
    meta.json         模型名、维度、来源清单
```

PDF 要 `pypdf`（venv 里已有 6.19.0，`requirements.txt` 没声明 —— 要长期用就补一行）。

### 换成零 API 成本的本地嵌入

D 盘那份 4.3G 的 `BAAI/bge-m3`（PyTorch 格式）只能被 sentence-transformers 加载，
fastembed 用不了它。想用它就走 `local` 后端：

```jsonc
// brain/config/config.json
"kb": { "backend": "local", "model": "BAAI/bge-m3" }
```

⚠️ 前提：**进程启动前** ROCm 的 PATH 必须配好（`kb/kb_core.py` 顶部解释了原因，
`kb/kb.bat` 就是干这个的）。没配好会在加载 torch 时报 WinError 126 ——
这时后端会自动退回 `api`，不会把聊天卡死。

换后端之后向量维度会变，**旧索引自动作废**（meta 里记着 model 与 dim，
对不上就整个不认，宁可重建也不拿两种模型的向量算余弦 —— 那不会报错，
只会一直返回看起来像结果的东西）。重建：

```bash
curl -X POST http://127.0.0.1:8788/api/plugin/kb/reindex -H "Authorization: Bearer <token>"
```

## 三、怎么用

### 导入

```bash
# 服务器上的文件或整个目录（递归，只收能读的格式）
curl -X POST http://127.0.0.1:8788/api/plugin/kb/ingest \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d '{"path": "D:/文档/手册"}'

# 直接给正文
curl -X POST http://127.0.0.1:8788/api/plugin/kb/ingest \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d '{"text": "……", "name": "临时笔记"}'
```

同一个 `name` 重复导入是**整份替换**，不是叠加 —— 改了文档重跑一次就行。

### 接口（都挂在插件命名空间下，没改 `server.py`）

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/plugin/kb/stats` | 块数、文档数、维度、模型、当前配置 |
| GET | `/api/plugin/kb/docs` | 已导入的文档清单 |
| GET | `/api/plugin/kb/search?q=&k=` | 检索测试（门槛为 0，方便看全貌） |
| POST | `/api/plugin/kb/ingest` | `{path}` 或 `{text, name}` |
| POST | `/api/plugin/kb/delete` | `{name}` 删除一个来源的全部块 |
| POST | `/api/plugin/kb/reindex` | 换模型后重建向量 |
| POST | `/api/plugin/kb/clear` | 清空本分区 |
| POST | `/api/plugin/kb/config` | 改开关与阈值（只认白名单键） |

### 自测

```bash
cd brain && python -m kb.selftest      # 真嵌入：摄入→三问→看分数→清干净
python -m unittest tests.test_kb       # 假向量：28 项逻辑单测，不联网
```

## 四、几个刻意的取舍

**1. 不引入向量库。** 语料量级是几千块，`vectors.npy` 暴力余弦是毫秒级。
多一个 Chroma/faiss 就多一份要同步、要迁移、要写进 requirements 的东西。
真到几十万块再换 ANN，那时只要改 `store.search()` 一个函数。

**2. 检索门槛默认 0.45，宁可不给。** 第一次接通时最容易出的问题不是"搜不到"，
而是"什么都搜得到" —— 把不相关的段落塞进提示词，她就拿别的文档内容回答你。
实测：相关查询 0.59 / 0.69，无关查询 0.36 → 拦住了。

**3. 注入和工具分开开关。**
`inject=true`（默认）：每轮自动检索注入，她不用先想到要查。
`inject=false`：只留 `kb_search` 工具，她需要时才查 —— 每轮省一次 embedding 调用。

**4. 知识库挂了不影响聊天。** 嵌入后端全挂时检索返回空、注入返回空字符串，
`on_turn_in` 里所有异常都被兜住并打日志。查不到就当没命中，绝不把对话拖死。

**5. 切块先按标题分节。** 跨节的块里两件事各占一半，向量变成平均值，谁问都匹配不上。
每块前面挂上标题路径（`安装 > 依赖`），块被拆出来之后语义还能找回来。

## 五、还没做的

- **文件级增量**：现在按来源整份替换，没做 mtime 比对 —— 目录大了要重跑全部。
- **文档解析**：`.docx` / `.xlsx` / 网页抓取都没有，只收纯文本类 + PDF。
- **重排（rerank）**：只做了一路向量召回，没接 reranker。
- **客户端界面**：桌面端的「知识库」页还只是排版稿（`docs/client-layout-v1.html`），
  没接这些接口。
- **权限**：`/api/plugin/kb/ingest` 能读服务器上任意路径。这是给本机/可信环境设计的，
  要不要加路径白名单取决于它跑在哪。
