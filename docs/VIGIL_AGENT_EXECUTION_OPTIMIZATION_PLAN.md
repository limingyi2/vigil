# Vigil 主对话与 Creator 多步任务执行优化方案

日期：2026-10-15（Asia/Shanghai）
状态：设计方案，尚未实施；不代表现有能力已经上线。
基线：本地 dev / Vigil 1.0.1，实施前重新核对 dev 与工作区差异。

## 1. 目标与范围

以可验证的任务完成作为成功标准。一次用户提交可以包含多次模型请求、工具执行、验证和修复；一次模型响应结束不等于整个任务完成。

本轮覆盖 Vigil 自身的主对话执行链与 Creator 插件生成。模型能力适配、模型结果归一化、流式事件和预算控制共用基础设施；普通问答与插件生成保留各自的执行策略和验证方式，不强迫所有聊天先生成计划。

包含：

- 移除按问题分类固定为 600 / 4096 的输出策略，改为模型能力与当前步骤需求共同决定。
- 主对话支持展示真实工具执行的多轮过程；Creator 支持文件计划、逐文件生成、验证和有限修复。
- 建立明确的成功、等待用户、预算暂停、取消、失败、中断边界。
- 延续多文件前端包、能力声明与宿主授权、审核后安装方向。

不包含：

- Codex 会话接管、GitHub 项目可视化插件业务。
- 通用 Task / Step / Attempt 恢复系统的阶段二实施；该工作线继续暂停。
- Brain 重启后自动续跑或自动重放有副作用的操作。
- 自动安装第三方依赖、无限调用模型、未经批准安装或运行生成插件。

## 2. 已核对的现状

| 入口 | 当前行为 | 需要解决的问题 |
|---|---|---|
| `brain.py:stream_chat` | 流式正文与思考展示；单次输出按分类设为 600 / 4096；此函数当前不支持工具调用 | 能展示流不等于能持续执行多步任务 |
| `brain.py` 工具循环 | 默认 24 轮、270 秒预算；按轮检查时间，超出后另作无工具收尾 | 固定轮次与聊天锁约束不适合长期工作；收尾不能冒充任务成功 |
| `brain/creator.py` | 非流式 `mp.chat()`，固定 4096，一次 JSON 携带文件内容 | 较大任务易截断；缺少逐文件验证与修复循环 |
| Creator 安装链 | 有草稿、静态验证、审批快照和事务安装 | 应复用，不能生成结束即自动安装 |

此表描述不同代码路径，不假定主对话所有请求都经过同一个工具循环。P0 必须补齐 `server.py` 路由、前端选择及降级路径图，避免重复执行。

## 3. 统一执行架构

```text
用户提交（request_id）
  → 服务端鉴权、请求去重、固定模型配置引用
  → 选择执行策略
      普通问答：直接回答，必要时调用工具
      多步任务：形成步骤与验收条件
      Creator：形成文件计划、接口与能力声明
  → 按步骤循环
      检查取消 / 预算 / 权限 / 输入大小
      → 调用模型 → 归一化结果与结束原因
      → 执行已授权工具或保存候选文件
      → 验证真实结果
      → 成功推进；失败修复；证据不足等待用户
  → 验收全部满足才成功，否则返回对应暂停或失败状态

显示订阅独立消费事件，不负责启动或重试执行。
```

基础模块建议置于 `brain/model_providers/` 与新的执行服务模块；命名在 P0 按现有代码确定。避免另建第二套模型配置、鉴权、审批和安装器。

主对话普通闲聊继续快速返回。明确多步操作走执行服务，不长期持有全局聊天锁；执行状态按认证主体、会话与 run 隔离，有副作用的共享资源另行串行化。用户后续消息默认不能隐式取消、改写或重新启动正在执行的任务。

## 4. 模型能力与单次输出策略

### 4.1 能力来源

按优先顺序使用：

1. 当前服务端的明确限制、经过校验的管理员配置。
2. 服务商模型元数据接口返回的能力。
3. 适配器维护的官方模型能力表。
4. 未知模式。

手动配置不突破已确认的服务端硬上限。能力记录至少包含服务商、规范化端点标识、模型 ID、输入/输出或共享上下文限制、参数名称、来源、更新时间和可信状态；不保存 API Key。缓存按端点与模型隔离，配置改变时重新解析，不能只按模型名称匹配代理。

模型自述不能作为上限证据；一次请求成功仅能说明该次可用。首次普通生成不进行昂贵的极限探测。

### 4.2 参数选择

- 已知能力时，输出额度结合当前步骤、上下文剩余空间和作业剩余预算分配，不必每次用满最大值。
- 区分独立输入/输出限制与共享上下文限制；先计算请求可容纳性，不能统一套用一个相减公式。
- 由适配器处理 `max_tokens` / `max_completion_tokens` / `max_output_tokens` 等差异，以及思考额度的提供者语义。
- 未知能力且接口允许省略时，不传输出上限，显示“服务端默认，上限未知”；省略不等于无限输出，也不保证更长。
- 接口必须传值时，优先使用管理员兼容配置；没有配置时暂用可配置的 4096，并明确标为兼容值，不能宣称探测得到。
- 参数拒绝仅在明确、可解析的上限错误下修正；最多自动修正一次，消耗计入预算。网络中断不能当作参数错误重发。

### 4.3 结果分类

提供者层统一输出：正文、工具调用、允许展示的推理摘要/内容、usage、结束原因、错误类别，以及是否完整结束。底层字段由各适配器解释。

至少区分正常结束、工具调用、长度截断、拒绝、服务错误、连接中断、仅思考无正文、无效结构。`[DONE]`、HTTP 200 或空正文都不能单独证明任务成功。usage 缺失时标为未知或估算，不伪造精确消费。

## 5. 主对话长任务策略

1. 建立简洁目标与验收条件，用户已经给出的要求直接沿用。
2. 根据工具结果安排下一步；各轮读取必要上下文，保留目标、已确认成果、当前步骤和错误摘要。
3. 使用结构化工具参数，完整解析并校验后才执行；不执行流式参数碎片。
4. 查询型失败可有限重试；写文件、移动、安装、外部发送等操作必须按实际结果核对。连接中断或结果未知时不能直接重做。
5. 达到验收条件后总结结果并引用证据；没有执行工具时不能声称已修改、已验证或已安装。

长文本问答达到长度限制时，按剩余章节继续，合并时避免重复；续写次数受单独配置与作业预算约束。普通问答不为“文本越长越好”无限追加请求。

上下文快满时优先裁剪重复工具输出、按需重读文件、压缩工作摘要。保留目标和关键约束，不能丢弃未确认操作的状态。摘要只帮助当前执行，不等于跨崩溃恢复保证。

## 6. Creator 完成驱动的生成策略

```text
需求与可验收功能
  → 文件计划、模块接口、能力声明
  → 路径与资源限制检查
  → 按依赖顺序生成候选文件
  → 单文件检查
  → 整包引用、入口、接口与权限检查
  → 有限修复失败项
  → 安全可用环境下预览 / 关键交互验证
  → 输出草稿及验证报告
  → 用户单独审批安装
```

大文件采用函数/模块拆分或带前置摘要校验的结构化修改，不依赖对截断源码机械拼接。候选内容与已验证版本分开保存，验证成功后才提升为有效版本。修改上游接口后，重新验证受影响文件；不能只看到单文件语法通过就结束。

完成条件：

- 约定功能有对应实现及验证证据，没有占位逻辑冒充实现。
- 文件齐全，入口、资源和模块引用正确，必要的静态检查通过。
- 能力声明与实际宿主动作一致，未知或未授权能力不能执行。
- 关键交互完成适用的验证；静态检查不能代替真实运行结果。
- 需要账号、授权、依赖或不支持的后端隔离时，列出“待验证”事项，不能标记为“功能已验证”。

草稿就绪只表示生成阶段完成，报告仍须区分“已验证”“待授权验证”“未验证”。审批、安装和运行验证属于独立草稿生命周期。

新包继续遵循现有 Creator 方案：受限前端、受控宿主桥、能力声明与版本/摘要绑定授权；没有可验证隔离时不启用生成的任意 Python 后端。任何 `frontend/` 或新格式标识均不得回退旧全权限加载路径。

## 7. 状态、预算与继续入口

执行生命周期与草稿安装生命周期分离。

| 执行状态 | 行为 | 后续 |
|---|---|---|
| `queued` | 已创建、未执行 | 调度后进入 running |
| `running` | 当前阶段执行 | 成功、等待、暂停或失败 |
| `waiting_user` | 缺授权、输入或必须确认的证据 | 同一进程内经明确动作继续 |
| `paused_budget` | 预算不足，停止新派发 | 授予预算后显式继续 |
| `succeeded` | 对应执行目标验收通过；Creator 为草稿生成结束 | 终态 |
| `failed` | 不可恢复或允许的修复已用尽 | 终态 |
| `cancelled` | 已停止调度 | 终态，另报告在途操作结果 |
| `interrupted` | Brain 重启或执行上下文丢失 | 终态，不自动续跑 |

analyzing / planning / generating / validating / repairing / assembling 用作 `stage`，不与上述生命周期重复建两套终态规则。Creator 对外如需 `draft_ready`，明确映射到 succeeded + draft_id。安装成功写草稿状态，不再改生成 run 的终态。

同一 run 的终态只允许原子持久化一次；完成与取消竞争以先提交的合法终态为准。取消成功不代表在途工具副作用已经停止；未知结果单独展示，禁止自动重放。

预算继续保留请求数、累计 token、总执行时间、单请求超时、文件资源限制及修复次数。预算配置单一来源；Creator 现有默认值可作为初始值，主对话按交互策略单独配置，不把 24 轮 / 270 秒简单复制为长期任务默认值。

- 预算到达只表示暂停，不表示完成。
- 追加预算修改上限，累计消耗不清零；额度必须覆盖继续所需消耗。
- 明确区分执行时间与绝对 deadline；等待用户时是否计时须在 P0 冻结，不能继续时暗中重置 deadline。
- usage 不可得时依靠请求数、时间和资源上限兜底；超过预算的在途调用完成后记录实际消耗，不假装能精确提前截停计费。
- 每步及每次模型调用前检查停止条件。重复修复无进展达到阈值则失败或等待用户，不循环碰运气。

建议操作接口：创建、读快照、订阅事件、取消、追加预算、继续、补充输入/授权。`grant_budget` 不隐式启动，`continue` 不隐式授予预算。创建及所有写动作均带稳定 request_id、鉴权与原子去重；只有允许状态才能认领执行，重复点击不能启动第二个执行器。

本期继续仅限当前进程仍持有有效执行上下文的 waiting_user / paused_budget。重启后变为 interrupted；用户可审阅保留成果后新建任务，不承诺无重复执行。跨重启继续留给暂停中的任务恢复工作线。

## 8. 流式协议与兼容

统一事件信封：run_id、单调 seq、type、时间和 payload；Creator 关联 job_id / draft_id。事件包含阶段、正文增量、可展示推理、工具开始/结束、文件状态、验证、usage、暂停、等待用户和唯一终态。

- 订阅/重连只读，不创建任务、不发模型请求。创建响应丢失后以 request_id 找回原 run。
- 执行终态持久化，有限事件缓存按游标补读；缺口返回快照与明确提示。
- 界面区分“本次响应结束”“等待工具”“等待授权”“预算暂停”“任务完成”。
- 服务端在发起工具前校验权限；前端不持有 Brain Token，仍走现有 Electron 代理。
- 生成源码按文本展示，不注入聊天 DOM；推理内容只展示提供者明确可展示的部分，不伪造，不进入长期检查点或插件文件。
- 对不支持模型原生流式的服务商，显示真实阶段并在结果到达后展示内容，不能模拟逐 token 作为真实流。

旧接口按动作分别适配：只有 POST draft / revise 创建生成作业并同步等待；列表、查询、验证、删除、审批和安装保持各自职责。旧响应保持 `{ok:false,err:...}` 等实际格式及原 HTTP 语义，新接口单独定义错误结构。

## 9. 开发顺序与阶段门槛

| 阶段 | 工作与交付 | 进入下一阶段的条件 |
|---|---|---|
| P0 契约收敛 | 路由图、能力来源和参数策略、执行/草稿双生命周期、预算计时、接口与事件样例；修正 Creator 契约冲突 | 状态转换、重发、取消、预算继续与旧接口兼容均可用样例解释，无悬空入口 |
| P1 模型适配 | 结果归一化、能力缓存、动态输出参数、长度/中断识别 | 已知模型、未知模型、强制参数、截断/空正文场景通过；不改变工具副作用 |
| P2 主对话执行与流 | 统一工具循环与订阅，按 run 管理并发、预算暂停、继续和取消 | 多步操作可观察；重复请求、重连不会重复执行；旧普通问答可用 |
| P3 Creator 多步生成 | 文件计划、候选写入、整包验证、有限修复、真实草稿报告 | 多文件生成与局部修复可验收；预算耗尽可继续；未验证项不冒充通过 |
| P4 包与授权 | 新格式安装、受限前端、能力桥与撤销；可沿用既有插件优化方案的分阶段实现 | 无越权或旧路径降级；审批摘要失效、安装失败回滚可复验 |
| P5 集成与发布准备 | 针对性回归、用户操作说明、已知边界与验收记录 | 明确记录完成/未完成项，再按用户授权提交、同步或发布 |

每阶段先交付可验收的小改动。新执行路径使用集中开关逐步启用；回退仅影响新请求，已运行任务不得因开关切换被重复调度。预算、事件和权限状态不能在不同路径各维护一份互不一致的数据。

## 10. 针对性验收

1. 已知模型不再统一使用 600 / 4096；代理同名模型缓存隔离；未知模式明确标记来源。
2. 必填输出参数仅使用明确兼容值；参数错误最多修正一次，网络异常不盲目重发。
3. finish_reason 为长度限制、仅思考、流中断时不误报完整成功。
4. 一次用户提交完成多个模型/工具轮次；前端显示真实阶段，工具参数碎片不能执行。
5. 重复创建、重复继续、订阅重连均不会增加一次工具执行或生成。
6. 一个通用多文件前端插件超出单次响应容量，仍可分步生成；验证失败仅修复受影响部分。
7. 被截断文件不替换有效文件；修复次数耗尽明确停止；上下游接口变更触发重新验证。
8. 预算耗尽保留有效成果；授予额度后显式继续，累计消耗不归零；未授予时不能继续。
9. 完成和取消竞争只有一个终态；已就绪草稿重启后仍可审核，未结束 run 标中断且不自动重跑。
10. 写操作结果未知时进入核对/等待；不能凭“没收到响应”重做。
11. 未授权联网/文件操作被宿主拒绝；授权撤销、身份错误、版本变化均失效。
12. 旧聊天、Creator 错误格式、草稿查询、审批安装链路保持兼容；一次针对性检查覆盖，不为无关模块扩大全量测试。

本期以模拟提供者、受控本机工具及无害测试面板验证。真实模型冒烟另行记录服务商、配置、实际 usage 与结果，不以无上限压力测试证明能力。
