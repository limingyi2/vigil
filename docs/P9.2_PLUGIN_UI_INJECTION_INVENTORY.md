Baseline: `ca371e2734dcdc2277026c9de78b17e84007f3ce` on local `dev`.

## Other code-execution surfaces

- Electron test scripts use `webContents.executeJavaScript()` to inspect and drive rendered application state. These are test harness operations, not production plugin loading; they should remain only in test code and must not be treated as proof of runtime isolation.
- The ordinary Core and settings windows already set `nodeIntegration: false`, `contextIsolation: true`, and `sandbox: true` in `client/electron/main.js`. They use the full Core preload, so these flags do not isolate plugin code that is executed inside the Core renderer.
- No plugin UI is currently hosted in a distinct `WebContents`; therefore there is no actual plugin renderer whose preferences, preload API, origin, or crash boundary can be verified.

## Required replacement boundary

The replacement must retain Core ownership of install, enablement, grants, and uninstall while assigning each enabled plugin UI a separately registered renderer. A generic descriptor (plugin identity derived from the host registration, page metadata, asset entry, and declared capabilities) is registered and revoked with plugin lifecycle. Plugin requests are routed through a main-process Broker that derives identity from the registered `WebContents`, validates origin/lifecycle/grants/operation schema, and denies unknown requests by default. Revocation must close the renderer and invalidate outstanding capabilities. Tests must inspect the live Electron renderer and exercise denial and crash cases, not only assert BrowserWindow preference literals.

## Inventory boundary and follow-up

This is a source-level inventory. Runtime tests will separately verify the effective WebPreferences, preload exposure, sender-to-plugin binding, revocation, resource path checks, and Core crash independence after implementation. HTTP endpoints and IPC handlers are listed by subsystem above; test harness-only `executeJavaScript` calls are intentionally not included as production injection paths.
