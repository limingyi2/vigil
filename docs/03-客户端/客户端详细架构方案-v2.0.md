**技术栈（实际）**：Electron 28（三重软渲染防御）· 原生 JS + styles.css · IPC/preload 白名单 ·
keytar+文件双写 token · PyInstaller sidecar 大脑 · REST+SSE · 1.5s HTTP 轮询 · electron-builder。

**消息延迟账本（2026-10-09 实测）**：轮转轮询 1.5–9s → 读屏 1–2s → 隧道 0.3s →
记忆检索 0.3s → （群非@时闸门 1–2s）→ 主模型 2–3.5s → 回发 2–3s；
全程感知 **~10–14s**（规划器 8–18s、自图回读双轮已砍）。

## 二、渠道与大脑拓扑（谁的话在哪处理）

| 渠道 | 处理大脑 | 人设绑定 persona_by_src | 历史/记忆分区 |
|------|---------|------------------------|--------------|
| 微信私聊 wechat | **云端** | `default`（老吴猫，用户定稿） | default.wechat.* |
| 微信群 wechat_group | **云端** | `default`（同上） | default.wechat_group.* |
| PC 客户端 pc | 本地 sidecar | `pc_assistant` | pc_assistant.pc.* |
| 手机 App app | 云端 | 全局 persona_file | *.app.* |

- 绑定权威源：**云端** `C:\Vigil\config\config.json`（runtime.py CFG_PATH）；
- M2 behavior 同步段现为四键：features / features_by_src / chatty / **persona_by_src**（10-09 补）——
  旧打包版不带新 sync_client，App 换绑定要到**下次重打包**后才真正通；
- 人设文件以 label 为 App 显示名：default.json 两侧均标 `老吴猫`；
- **教训存档**：查"人设没生效"三层——绑定 → 同步覆盖 → 同名文件内容（云端 default.json
  曾是八奈見杏菜，本地才是猫）。

## 三、v2.0 愿景裁决表（冲突全部了结）

> 图例：✅ 已完成（含等效实现）｜♻️ 改造采纳（形态变了）｜⏸️ 暂缓（有触发条件）｜❌ 放弃（理由在此存档，别再翻出来）

| v2.0 愿景项 | 裁决 | 现状 / 理由 |
|------------|------|------------|
| Electron 30+ 桌面框架 | ✅ | Electron 28 在跑；非 LTS 追新无收益 |
| React 18 + TypeScript + Zustand | ⏸️ | 页面仅 5 个、单人维护，原生 JS 成本更低。**触发条件**：页面 >8 个或多人协作时再议 |
| Tailwind + shadcn/ui | ❌ | 与"无构建链"冲突；styles.css 单文件 + 主题变量已覆盖 |
| react-markdown + remark-gfm | ♻️ | 自写 ui.js `md()/inline()`；缺口=[img:NAME] 不渲染 → 进 P0 |
| better-sqlite3 本地聊天库 | ⏸️ | JSONL 分区存档够用。**触发条件**：历史 >10 万条或要做全文检索 |
| 任务调度器（队列/取消/优先级/回滚） | ✅ 等效完成 | localtool 三档 risk + 确认弹窗（=取消）+ oplog 备份撤销（=回滚）+ 1.5s 单队列轮询（=调度） |
| 本地操作层 + 权限沙箱 | ✅ | localtool 白名单/系统目录硬拦/DANGER 集 + 服务端 risk 双保险 |
| Windows-MCP 集成（8765） | ❌ | 与 localtool 白名单体系冲突（两套权限模型=两倍攻击面）。工具需求继续走 localtool CATALOG 扩充 |
| 监控面板（大脑状态/Token/显存） | ♻️ | 数据页已有 stats+chart；**缺云端视角** → 进 P0；显存不做（GPU 已整体禁用，无显存可言） |
| WebSocket 心跳/重连 | ❌ | 轮询+SSE 已覆盖；WS 还要改隧道/反代，收益为零 |
| 云端连接层 REST | ✅ | 主进程统一代理 + 鉴权头 |
| 本地模型 Ollama（11434 混合模式） | ♻️ | 不做硬编码混合开关；模型选择已由"模型与接口"向导承担（/api/models 动态渲染，无写死列表）。要用本地 Ollama = 在大脑侧加一个 provider，客户端零改动 |
| 本地通信 child_process | ✅ | sidecar.js（就绪行/崩溃重启/taskkill 收尾） |
| 数据层 config.toml | ❌ | 沿用大脑的 config.json，别造第二套配置 |
| 人设缓存 + 云端同步 | ✅ | M2 同步（四键）+ M5 设置页云端同步子页；persona_by_src 10-09 补入 |
| 快捷键 | ⏸️ | P2 小项，随包顺带 |

**结论**：v2.0 里真正还要"做"的只剩 3 件事（见下节 P0），其余要么已完成、要么明确放弃。

  配置看那里，不是仓库 brain/；

## 六、模块速查（改代码前先看这）

| 文件 | 职责 | 红线 |
|------|------|------|
| electron/main.js | 窗口/托盘/配置/token/HTTP/SSE/设备注册/双轮询 | 渲染层永不碰 token；轮询双队列别合并 |
| electron/sidecar.js | 大脑子进程生命周期 | 退出必须 taskkill /T，防孤儿占端口 |
| electron/localtool.js | 20 工具目录 + 风险 | 新工具必须标注 danger 组；写类必须带备份 |
| electron/forward.js | 云端→本地转发 | 只在本地大脑 ready 时启 |
| electron/oplog.js | 操作留痕 | 每个她执行的动作都要落一条 |
| src/js/pages.js | 五页渲染 | 无框架约定：直接 DOM，别引运行时依赖 |
| src/js/ui.js | 气泡/md/确认 | [img:] 渲染改这里（P0-1） |
| preload.js | 白名单桥 | 只加方法，不开口子 |
