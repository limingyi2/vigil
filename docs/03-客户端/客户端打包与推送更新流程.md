# 客户端打包与推送更新流程

> 最后更新：2026-10-09
> 适用版本：v0.1.2 (code=8)

## 一、整体架构

```
client/          Electron 客户端源码
  ├── electron/        主进程（main.js, sidecar.js, preload.js）
  ├── src/             渲染层（HTML/CSS/JS）
  ├── package.json     依赖 + electron-builder 配置
  └── version.json     客户端版本号（code 递增）

brain/                 Python FastAPI 大脑
  ├── server_launch.py 打包入口（含技能宿主自动启动）
  └── skill_host/      Node.js 技能宿主

deploy/
  ├── vigil-brain.spec          PyInstaller 打包配置
  ├── deploy_client_v011_20261009.py  客户端推送脚本
  └── sshkeys/                  SSH 部署密钥

dist/
  ├── vigil-brain/              PyInstaller 打包产物（brain exe）
  └── VigilSetup.exe            客户端安装包（待上传）
```

## 二、版本号规则

| 文件 | 字段 | 说明 |
|------|------|------|
| `client/version.json` | `code` | 整数，每次发布 +1，客户端用它判断是否有更新 |
| `client/version.json` | `ver` | 语义化版本号（如 0.1.2），仅展示用 |
| `client/package.json` | `version` | 必须与 version.json 的 ver 一致 |
| 云端 `client_version.json` | `code` | 必须比客户端本地 code 大才会提示更新 |

**重要**：`code` 是更新判断的唯一依据，`ver` 只用于展示。

## 三、打包流程（完整步骤）

### 步骤 1：重新打包 brain（如果 brain 有改动）

```bash
cd F:\Vigil
venv\Scripts\python.exe -m PyInstaller --noconfirm deploy\vigil-brain.spec
```

产物：`dist/vigil-brain/vigil-brain.exe` + `_internal/`

验证：
```powershell
# 确认 skill_host 已包含
Test-Path "dist\vigil-brain\_internal\skill_host\server.js"
```

### 步骤 2：更新客户端版本号

编辑 `client/version.json`：
```json
{
  "code": 9,
  "ver": "0.1.3"
}
```

同步修改 `client/package.json` 的 `version` 字段。

### 步骤 3：打包客户端

```bash
cd F:\Vigil\client
npm run dist
```

产物：
- `dist/Vigil Setup 0.1.3.exe` — NSIS 安装包
- `dist/Vigil 0.1.3.exe` — 绿色便携版
- `dist/win-unpacked/` — 解压版（调试用）

验证 brain 是否包含：
```powershell
Test-Path "dist\win-unpacked\resources\vigil-brain\vigil-brain.exe"
```

### 步骤 4：准备推送文件

```powershell
# 复制安装包到统一位置
Copy-Item "client\dist\Vigil Setup 0.1.3.exe" "dist\VigilSetup.exe" -Force

# 计算 SHA256
(Get-FileHash "dist\VigilSetup.exe" -Algorithm SHA256).Hash.ToLower()
```

### 步骤 5：推送到云端

修改 `deploy/deploy_client_v011_20261009.py`：
- `NOTES` 更新为本次更新说明
- `vf = {"code": 9, "ver": "0.1.3", ...}`

运行：
```bash
cd F:\Vigil
venv\Scripts\python.exe deploy\deploy_client_v011_20261009.py
```

脚本会自动：
1. 备份云端旧版本
2. 上传 VigilSetup.exe 到 `C:\Vigil\app\client\`
3. 校验远端 SHA256
4. 写入 `client_version.json`
5. 验证远端目录

### 步骤 6：验证推送

```powershell
$headers = @{ "Authorization" = "Bearer <你的token>" }
Invoke-WebRequest -Uri "http://203.0.113.10:8788/api/client/version" -Headers $headers
```

确认返回的 `code` 是新版本号。

### 步骤 7：客户端更新

用户重启客户端，15 秒后自动检测更新：
1. 对比云端 code > 本地 code
2. 弹窗提示更新
3. 后台下载安装包（SHA256 校验）
4. 下载完成后弹窗"立即安装"
5. 启动安装向导，退出客户端，覆盖安装

## 四、云端更新接口

### 版本检查
```
GET /api/client/version
Header: Authorization: Bearer <token>
```
返回：
```json
{
  "code": 9,
  "ver": "0.1.3",
  "notes": "更新说明",
  "sha256": "安装包的sha256",
  "size": 161206263
}
```

### 安装包下载
```
GET /api/client/setup
Header: Authorization: Bearer <token>
```
返回：二进制文件流（分块 256KB）

### 云端文件位置
```
C:\Vigil\app\client\
├── VigilSetup.exe          当前版本安装包
├── VigilSetup.exe.bak      上一版本备份
├── client_version.json     当前版本信息
└── client_version.json.bak 上一版本备份
```

## 五、常见问题

### Q: 客户端没提示更新？
A: 检查三点：
1. 云端 `code` 是否 > 客户端本地 `code`
2. 客户端是否配置了云端同步（cloud_url + cloud_token）
3. 客户端启动后是否等够 15 秒（启动后 15 秒才第一次检查）

### Q: 更新后本地大脑连不上（ECONNREFUSED）？
A: v0.1.2 已修复。api 请求优先用 sidecar 动态发现的端口，不再用配置里写死的 `cfg.base`。

### Q: 技能宿主没起来？
A: v0.1.1 已修复。brain 启动时会自动拉起 skill_host，打包时已包含 `_internal/skill_host/`。

### Q: 打包后 brain 找不到 skill_host？
A: 检查 `deploy/vigil-brain.spec` 是否包含 `skill_host_data`，打包后确认 `_internal/skill_host/server.js` 存在。

| `client/electron/sidecar.js` | brain 子进程管理 | 修改 brain 生命周期时 |
| `client/package.json` | 依赖 + electron-builder 配置 | 新增依赖/打包配置时 |
| `client/version.json` | 客户端版本号 | 每次发布时 |
| `deploy/deploy_client_*.py` | 推送脚本 | 每次发布时更新 code/notes |
