# 打包与发布

本文对应 `dev` 分支的 Electron 与 Brain 统一安装包。版本文件为 `client/version.json`，构建入口为 `scripts/build_release.py`。

## 版本

发布前同步修改以下字段：

| 文件 | 字段 |
| --- | --- |
| `client/version.json` | `ver` 与递增的整数 `code` |
| `client/package.json` | `version` |
| `client/package-lock.json` | 顶层与根 package 的 `version` |

客户端按 `code` 比较更新。正式标签使用 `v<ver>`，并与发布说明 `docs/releases/v<ver>.md` 对应。已推送标签不应移动到另一个源码快照。

## 候选构建

环境为 Windows、Python 3.12 和 Node.js 22。安装 Brain 构建依赖与锁定的客户端依赖后，在仓库根目录运行：

```powershell
.\.venv\Scripts\python.exe -m pip install -r brain/requirements.txt pyinstaller pypdf
npm ci --prefix client
.\.venv\Scripts\python.exe scripts/build_release.py --candidate
```

候选安装包及清单位于 `client/dist-release/`。GitHub 的 `windows-market-candidate.yml` 在相应改动提交到 `dev` 或 PR 时执行构建、哈希核对和隔离安装验收。候选清单中的 `candidate` 为 `true`，不能直接改字段后充当正式包。

## 正式发布

1. 合入已完成检查的源码，确认版本、更新日志与发布说明一致。
2. 创建并推送对应版本标签。
3. `windows-release.yml` 构建非候选安装包，校验版本、提交、大小和哈希。
4. 同一份安装包在 Windows runner 上执行新装、专家接口、聊天、重启恢复、插件生命周期和卸载数据保留检查。
5. 验收完成后上传 Release，并标记为最新版。

工作流会在安装验收前归档构建产物。正式包与候选包通过显式参数区分，两种模式均保留来源和哈希校验。

## 发布文件

| 文件 | 用途 |
| --- | --- |
| `Kestrel.Setup.<ver>.exe` | Windows NSIS 安装程序 |
| `Kestrel.Setup.<ver>.exe.blockmap` | 差分下载信息 |
| `Kestrel.Setup.<ver>.contents.json` | 安装内容哈希 |
| `release-manifest.json` | 版本、整数 code、源码提交、安装文件名、大小和 SHA-256 |

`dist/brain-release/vigil-brain/` 是随包 Brain 的中间产物，包含构建身份和 Brain 文件清单。`client/dist-release/win-unpacked/` 用于检查打包内容，不是单独的发布验收结论。

正式更新由 GitHub Release 提供，不再通过旧云端部署脚本、APK 路径或 `client_version.json` 分发。当前安装包不包含桌宠；引入任何外部组件前应核实其分发许可与运行依赖。

## 验证范围

安装报告分别记录各项状态。现有未签名 P21.2 旧包在 Windows runner 上存在启动问题，签名历史版本升级保持 `BLOCKED`；用户实际电脑的升级状态另列。不要把新装通过写成历史升级已通过。

失败时保留工作流日志、构建清单和生命周期报告，核对具体失败阶段。不要为使验收通过而改写候选标志、哈希或已有结果。
