> 最后更新：2026-10-09
> 状态：待执行
> 目标：将客户端、大脑、部署工具等子项目分离，使项目结构清晰、易于维护

## 一、重构目标

### 1.1 核心原则

1. **按子项目拆分**：每个独立功能模块有自己的目录，包含源码、配置、依赖说明
2. **共享资源集中**：文档、部署脚本、工具脚本放在统一位置
3. **产物与源码分离**：打包产物、缓存、日志不进 git
4. **路径最小改动**：重构后尽量少改代码里的相对路径

## 四、风险评估

### 4.1 高风险操作

| 操作 | 风险 | 缓解措施 |
|------|------|---------|
| brain/ 源码移动到 brain/src/ | import 路径全部失效 | 先做依赖分析，逐步移动，每步测试 |
| client 重命名为 client | 所有路径引用失效 | 全局搜索替换，打包测试验证 |
| wechat_bridge 重命名 | 部署脚本路径失效 | 更新部署脚本，测试部署 |

### 4.2 中风险操作

| 操作 | 风险 | 缓解措施 |
|------|------|---------|
| deploy/ 脚本整理 | 找不到某个脚本 | 先移到 archive/，确认无用再删 |
| dist/ 目录重组 | 推送脚本找不到安装包 | 更新推送脚本，测试一次完整流程 |

### 4.3 低风险操作

| 操作 | 风险 | 缓解措施 |
|------|------|---------|
| 文档移动 | 无 | 文档不影响代码运行 |
| 创建快捷脚本 | 无 | 新增文件，不影响现有功能 |
| 更新 .gitignore | 无 | 只影响 git 提交 |

## 五、执行顺序建议

### 推荐顺序（从低风险到高风险）

1. **阶段 1：文档整理**（低风险，立即可以做）
2. **阶段 7：创建快捷脚本**（低风险）
3. **阶段 8：更新 .gitignore**（低风险）
4. **阶段 2：部署工具整理**（中风险，先归档不删除）
5. **阶段 6：dist 目录整理**（低风险）
6. **阶段 5：微信桥接整理**（低风险）
7. **阶段 3：客户端重命名**（中风险，需要全局替换+测试）
8. **阶段 4：大脑源码整理**（高风险，建议最后做，甚至可以不做）

### 可以跳过的阶段

- **阶段 4（大脑源码整理）**：如果 brain/ 当前结构已经够用，可以不做。移动源码到 src/ 的收益不大，但风险很高。
- **阶段 3（客户端重命名）**：如果 client 这个名字你觉得没问题，可以不改。改名字主要是为了统一命名风格。
