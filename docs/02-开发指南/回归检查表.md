# 回归检查

## 提交前

- 确认工作区只包含本次改动，排除配置、密钥、数据、日志与临时实验文件。
- 对修改的 Python 和 JavaScript 文件执行语法检查。
- 运行相关测试；行为变化应有能够覆盖问题的回归。
- 执行 `git diff --check`，核对路径、字段和状态值的变化。

基础命令与环境见 [参与开发](../../CONTRIBUTING.md)。全量单元测试、真实 FAISS 和语法检查由 `tests.yml` 执行，不采用“允许固定数量失败”的旧基线。

## 按改动范围检查

| 范围 | 需要核对 |
| --- | --- |
| 模型与工具 | 参数、模型能力、工具清单、授权、错误与结果未知状态 |
| 会话与资料 | 人设/来源/会话范围、切换、附件、重启恢复与原始数据保留 |
| 插件与技能 | 安装、启停、卸载、重启与用户数据处理 |
| Electron | preload、IPC、事件订阅、页面切换和进程退出 |
| 版本与打包 | 客户端和 Brain 身份一致、清单哈希、真实安装与卸载保留 |
| 文档 | 当前与历史状态、示例命令、相对链接和图片路径 |

## 发布

候选和正式包分别按对应模式验收，不能修改清单标志充当另一种构建。记录新装、重启、插件生命周期、历史升级和用户真机测试各自的结果。发布文件和步骤见 [打包与发布](../03-客户端/客户端打包与推送更新流程.md)。

旧云端、微信桥接与 APK 流程不是当前桌面发版步骤，需要维护历史环境时单独核实适用版本。
