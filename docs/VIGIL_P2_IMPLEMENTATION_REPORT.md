# Vigil P2 Agent 执行循环交付记录

基线：`p2-agent-execution`，`7d350c87c877d3cbbd10d8273799af929db1f4c2`。
本轮只实现 Agent 执行循环、预算停止、取消、去重与记录恢复，不扩展插件权限，不实施 P3/P4，不执行生成代码。

## 实现内容

- `brain/agent_runs.py`：SQLite 持久化 run_id、request_id、状态、阶段、步骤、工具派发账本、部分正文、结果、错误原因和事件游标。
- 按现有模型配置调用 P1 的 `prepare` / `completion_events`；模型 → 结构化工具调用 → 工具结果 → 模型循环。流式工具参数必须完整收齐并通过 schema 校验后才可派发。
- `brain/model_providers/execution.py` 补齐原生 SSE 工具调用片段聚合。无原生流时直接使用实际完整响应，不模拟 token。截断、仅思考、坏结构、服务错误、断线都停止，不自动重试或切换另一条执行链。
- 复用 `tools.all_specs` / `tools.invoke_spec`、渠道 ContextVar、现有本机能力授权与确认。动态工具采用其已公布的 schema；不支持的 schema 校验关键字会拒绝执行。
- 本机工具增加内部结构化回执，原有字符串返回保持兼容。离线、拒绝、未派发、结果不明不再作为成功工具结果继续驱动执行。
- 重启后非终态标记 `interrupted`，在途步骤保留未知结果，不自动续跑。

## 接口与桌面入口

所有新接口均要求管理员身份，并按身份、渠道、会话校验归属；知道 run_id 不构成授权。受限设备权限白名单没有扩大。

| 接口 | 行为 |
|---|---|
| POST `/api/agent/runs` | 稳定 request_id 原子去重创建，接受 intent 或 text |
| GET `/api/agent/runs` | 最近 200 条可见 run |
| GET `/api/agent/runs/<id>` | 持久快照 |
| GET `/api/agent/runs/<id>/events?after=<seq>` | 有限缓存、只读 SSE 订阅，缺口/停止状态返回快照 |
| POST `/api/agent/runs/<id>/cancel` | 幂等取消后续派发 |

桌面管理员主对话中，有稳定 request_id、纯文本、需要工具的 `/api/chat/stream` 新请求接入 Agent Run。既有 Electron 代理保持不变。界面显示真实阶段、正文、可展示思考和取消按钮；刷新从 `/api/history` 的 run 展示投影恢复，运行中的记录仍可取消。

普通问答、附件/图片、旧的无 request_id 请求及同步聊天接口继续保持兼容路径。Creator 的 job、草稿与安装生命周期保持原职责。这里不将全部旧入口强制迁移为新执行器。

`agent_execution.enabled=false` 只使新的主对话请求走兼容路径。已存在的 run 重发仍归原 run；旧展示记录存在时也不会迁移后重新执行。

run 仅持有自己的工具对话。快照人设与既有上下文时使用原聊天锁，不让后台执行器修改共享 Brain 的 history/last_* 字段。同身份、渠道、会话最近 8 条中的成功 run 可作为后续任务上下文；失败、部分输出、原始错误和思考不进入该上下文。

## 预算与停止

唯一配置入口为现有 config.json 的 `agent_execution`，经 `runtime.API_CFG_KEYS` 保留。

| 配置 | 默认值 | 含义 |
|---|---:|---|
| max_steps | 40 | 模型步骤和新工具步骤总数 |
| max_requests | 16 | 模型调用次数 |
| max_tool_calls | 24 | 新工具派发次数 |
| max_seconds | 600 | 本次执行时间预算 |
| request_timeout | 90 | 单模型请求超时秒数 |

创建请求中的 budget 只能降低配置额度，零值、布尔值、负值、未知字段或超上限均拒绝。每个模型/新工具步骤前检查预算；模型流中也检查时间。输出参数仍按 P1 的能力适配，不恢复固定 600/4096 分类上限。部分正文与单工具结果沿用有限资源保护（65536 字符），超限明确失败。

预算用尽进入 `paused_budget`，不补发一次模型来强行收尾。此状态可取消；本轮没有实现追加预算、显式继续或跨重启续跑，相关动作返回不支持。已派发调用无法精确提前截停计费；时间预算用于阻止后续派发。

## 去重与取消的保证边界

1. `(owner, request_id)` 唯一约束和事务认领保证重复提交不会启动第二个执行器；输入变化复用原 ID 会拒绝。读快照、刷新与订阅不会生成。
2. 工具先提交派发意图，再调用现有工具系统；同一 call_id 不得对应不同名称/参数。
3. 有副作用及未知工具按 run 内「工具名 + 规范化 args」去重；即使换调用 ID，完成结果也复用。同 ID 的已知只读工具也去重；已知只读工具使用新 ID 可重新读取，使“读 → 写 → 再读验证”取得新数据。低风险的打开网址/截图不等于只读，未列入只读集合。
4. 工具异常、结果不明或进程退出后没有自动重放。这个保证针对同一个 run 内的调用身份与规范化参数；不宣称能判断路径别名、不同参数或不同 run 的操作在语义上等价，也不宣称外部系统具备事务性 exactly-once。
5. 取消原子停止后续调度；排队但未被本机客户端认领的工具会拒绝认领。已经认领/派发的工具可能仍完成，快照单独保留在途和迟到结果，run 的 cancelled 终态不被覆盖。
6. 思考增量只保留于有限内存缓存。持久快照、数据库事件与错误摘要不保存完整推理或提供者原始异常报文；显示部分正文不代表目标已验证。

已知 XML 兼容提供者继续遵守原有显式 opt-in 和工具白名单，使用既有解析器。其旧兼容模式为一批工具后总结；原生结构化工具路径支持多轮。普通正文中的 XML 不会获得执行权限。

分组执行关键测试，没有重跑全仓测试；模型与本机工具均为模拟或本机 HTTP fixture，没有真实服务商调用或真实文件副作用。

组合回归中 Creator 的截断测试曾出现一次 `connection_lost`；其单项复验及完整 Creator 23 项隔离复验通过。保留此观测，不将其描述为从未出现失败。

Electron 使用隔离 userData 和 IPC 服务替身，不将其等同于生产主进程代理到真实服务商的全链路验证。真实 Brain 冒烟则使用实际子进程、HTTP handler 和模型适配，仅模型端是本机 fixture。

## 未验证与剩余范围

- 未验证真实服务商、真实设备在执行文件操作中断电/重启、第三方插件全部 schema 或长时间高并发。
- 未重新打包安装程序，本轮交付源码分支。
- 未实现预算追加/继续、跨进程恢复执行、P3 分文件生成修复、P4 新能力授权或插件开发。
- 第三方字符串工具缺少结构化回执时，不能推断其外部副作用的事务性；异常按未知结果停止。未知工具保守去重可能阻止同一 run 中有意重复的同参数操作。
- 去重账本保留用于防重放，尚无长期账本归档/压缩策略；可见列表限最近 200 条。清除会话仅隐藏展示，不取消执行或删除草稿。
