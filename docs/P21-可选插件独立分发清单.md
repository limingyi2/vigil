# P21 可选插件独立分发清单

本文记录 P21 零插件打包边界下的功能归属和迁移状态。仓库中存在源码不代表客户端会打包或安装它；新安装只包含明确批准的核心适配器和 Skill Host 基础设施。可选插件必须由插件市场或其他明确安装流程写入 `data/installed_plugins/`。

## 当前功能归属

| 功能 | 源码/能力 | 新安装状态 | 旧版升级及用户影响 | 独立发布状态 |
| --- | --- | --- | --- | --- |
| 插件市场 | `brain/core_features/plugin_market.py`：浏览市场、校验并事务安装/更新/卸载 | 核心基础设施保留 | 可管理已安装插件 | 核心，不单独发布 |
| 本机 Agent 工具 | `brain/core_features/remote.py`、`brain/localtools.py`：本机能力登记和授权工具桥 | 核心适配器保留；具体危险操作仍受客户端授权策略约束 | 原有 Agent 工具链保留 | 核心，不单独发布 |
| Skill Host | `brain/core_features/skill.py`、`brain/skill_host/server.js`：发现并调用用户通过 Skill 流程安装的 JS 技能 | 宿主保留；不从客户端安装包播种技能包 | 已安装技能及数据留在用户目录 | 技能包按现有 Skill 安装流程独立安装 |
| 本地知识库插件 `kb` | `brain/plugins/kb.py`：知识库页面/API 和逐轮自动检索接线；底层引擎 `brain/kb/` 及 Agent 的 `knowledge_base` capability 仍属于 Brain | 新安装保留知识库引擎和 Agent capability；不含插件 UI/API 路由及自动逐轮注入。`kb_search` 插件工具也不由 Plugin Host 提供 | 旧版插件源会复制到 `data/installed_plugins/`；知识库索引和文档数据保留 | **尚无市场制品**；优先发布，需验证旧数据和底层引擎兼容 |
| ReAct `react` | `brain/plugins/react.py`：拆分模型思考/动作/面向用户回复并保留 trace | 未安装时不执行插件钩子 | 旧版副本迁移后继续可用；其 trace 数据不由迁移删除 | **尚无市场制品**；需确认记录隐私与设置说明后发布 |
| 提醒 `reminder` | `brain/plugins/reminder.py`：自然语言提醒、到期主动通知 | 新安装不含提醒功能 | 旧插件迁移；`data/plugins/reminder/` 中的数据保留 | **尚无市场制品**；需覆盖后台生命周期、时区和持久化后发布 |
| 联网搜索 `websearch` | `brain/plugins/websearch.py`：显式联网搜索工具和缓存 | 新安装不含搜索工具 | 旧插件迁移；用户搜索配置和数据不清理 | **尚无市场制品**；需公布服务依赖、联网行为和失败表现后发布 |
| Branch Atlas `branch-atlas` | `brain/plugins/branch-atlas/`：只读查看本地 Git 分支/提交图和工作区状态 | 新安装不含该可选开发者工具 | 旧目录包迁移后保留；需在有 Git 的本机 Brain 上运行 | **尚无市场制品**；作为显式可选开发者扩展发布，不恢复为内置插件 |
| Wallpaper | 独立 `vigil-plugins` 市场包 | 不随客户端安装；用户在插件市场安装 | 已安装版本和壁纸数据保留 | `market.json` 当前登记 4.2.0，使用独立 ZIP 和 SHA-256 校验 |
| `calc`、`gate`、`meme`、`sticker_pack` | P21.2 已下线的旧功能/桥接兼容代码 | 不提供 | 迁移明确跳过这些退役插件，但保留旧源码和数据，不自动删除 | 不从旧目录复活；如有新需求须单独提出并独立发布 |

## 升级行为

- 迁移只复制旧插件源码到 `data/installed_plugins/`，保留原始目录和插件数据；复制失败会报告错误，保留源文件并允许之后重试。
- 即使旧插件副本与历史随包字节完全相同，也按用户曾获得该功能处理并迁移。
- 已有市场版本或用户修改版本优先，不被旧源码覆盖。迁移回执会记录已处理来源；用户卸载后，后续启动/升级不会再次导入同一旧副本。
- `plugin_market`、`remote`、`skill` 是显式允许的核心适配器；不从旧插件目录迁移。知识库数据、聊天记录、配置、数据库和插件数据不属于可清理的打包文件。

## 独立发布计划

本 PR 不伪造缺失的市场包，也不增加 Manifest 版本。每个插件都应使用仓库现有 Manifest v1、SHA-256、静态结构校验、权限检查和事务安装流程，分别完成：

1. 从历史源码制作可下载的独立 ZIP，并提交到独立插件仓库；市场目录登记版本、权限、协议、URL 和制品哈希。
2. 用干净用户目录验证安装、重启加载、启停、升级回滚、卸载及卸载后升级；验证插件数据是否保留。
3. 发布前更新本清单中的状态和用户说明。市场目录出现制品之前，不能把该功能标成“已独立发布”。

建议顺序：先 `kb`（影响本地知识库页面和聊天检索），再 `reminder` 与 `websearch`，然后 `react` 和 Branch Atlas。此顺序是发布计划，不代表包已制作或发布。已有用户可通过旧版插件迁移继续使用；新安装用户须等待对应独立市场制品。
