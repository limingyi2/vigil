# P9 数据迁移与回滚约定（P9.0）

本文定义未来扩展化需要遵守的数据保护流程；本阶段不执行迁移，也不改动现存数据。

## Wallpaper

### 必须保留的数据

迁移前必须盘点并保留 Electron `userData/wallpaper-engine` 下的设置/配置、素材、上传项目、缓存、缩略图、转码/预览文件及引擎自身可识别的其他状态。Steam Workshop 内容与用户自定义目录是外部用户资产：不得移动、改名、覆盖或在扩展禁用/卸载时清理。缓存可以标记为可重建，但只有在用户明确选择清理时才删除。

另有旧版 Brain 插件数据 `.vigil/wallpaper/config.json`。迁移只允许只读探测、解析和报告字段；不得自动把它覆盖到新配置。旧文件可能服务于另一套旧 API，不能假定与 Electron Wallpaper 数据语义相同。

### 幂等复制、验证、提交

1. 检查源与目标真实路径，拒绝符号链接逃逸、路径穿越、目标为源目录父级或覆盖非空用户目录。
2. 在目标同卷建立独立 staging 目录；记录迁移 ID、源清单、文件大小与 SHA-256。跳过目标已有且哈希相同的文件；冲突则保留双方并报告，绝不静默覆盖。
3. 复制到 staging，验证文件清单、哈希、大小、权限及格式。迁移可重复运行；同一源清单不会重复导入或改变已提交数据。
4. 以原子 rename/版本指针切换提交，并写出不含私密路径细节的迁移收据。只有新扩展启动及用户资产检查通过后才标记完成。
5. 保留源数据与 staging 快照至少一个完整回滚周期。失败时删除本次 staging（仅限验证过的 staging 根），恢复旧指针/旧实现读取路径；源文件不变。

扩展禁用或卸载只停止程序和 IPC、移除程序文件，不删除配置、素材、上传项目、Steam Workshop 内容、自定义目录、缓存或缩略图。回退时先禁用扩展，再让旧实现从原数据根读取；若新格式已写入，须提供兼容只读适配器或从迁移快照还原，不反向猜测性转换。

## WeChat Bridge

- 微信登录态始终留在专用桥接运行机；不迁入 Vigil Core、桌面用户目录或扩展包。
- 真实 token、登录态、账号/联系人标识不得写入 Manifest、日志、命令行参数、聊天历史、普通 UI 或错误报告。凭据迁移只能通过受保护的秘密通道/凭据存储完成；审计只报告字段迁移状态，不回显值。
- 迁移前后 `pc`、`wechat`、`wechat_group` 的历史、人设、记忆和权限隔离必须一致。渠道身份必须由受信任适配器映射，不接受客户端任意指定来扩大授权。
- 必须保持私聊 owner 校验、群聊 safe-only、remote control 默认关闭。Bridge 无法确认身份、owner 配置或渠道类型时，拒绝高权限操作并采用安全降级；不得将群聊错误识别为私聊。
- 兼容期旧 `/api/chat`、`msg/ack/result` 和可选双 Brain `ws_forward` 由单独适配层映射。请求要有 correlation/idempotency key，取消/迟到响应不能造成重复发消息。双 Brain 转发单独启用和迁移，不跟随 Bridge 自动开启。
- 如果旧配置或凭据迁移失败，保留旧配置及旧服务原状态，不自动删除、重置或轮换。修复后可重跑；报告中只能列出失败字段名/阶段，不包含字段值。

## 回滚验收

每次迁移需在无真实微信登录、无真实消息的隔离环境中证明：源数据哈希不变；中途终止可安全重跑；验证失败不切活动版本；禁用/卸载不删除用户资产；回切后旧实现可读取源配置；脱敏日志不含 token 或账号标识。真实桥接运行机的恢复演练需单独授权和安排，不由静态测试代替。
