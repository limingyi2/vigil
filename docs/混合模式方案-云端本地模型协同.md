# 混合模式方案 — 云端大模型 + 本地 27B 模型协同

## 一、设计目标

- **聊天只走云端**：人设对话、日常交流用云端模型（DeepSeek/Mimo），保证拟人化和推理能力
- **脏活累活给本地**：文件批量处理、代码生成、长文本摘要、数据清洗等走本地 27B，不消耗云端额度
- **一个开关控制**：客户端一键切换"纯云端" / "混合模式"
- **主模型调度**：云端主模型通过 function calling 决定什么时候调用本地模型，用户无感知

## 三、任务分配策略

### 3.1 走本地模型的任务

| 任务类型 | 原因 | 示例 |
|----------|------|------|
| **批量文件处理** | 数据量大，走云端费 token | 整理 100 个文件、批量重命名、格式转换 |
| **代码生成/审查** | 本地模型代码能力够用，省额度 | 写脚本、审查 diff、重构建议 |
| **长文本摘要** | 输入长，云端贵 | 总结一篇 5000 字文档、提取要点 |
| **本地文件问答** | 数据不出本机，隐私好 | "这个项目里的 XXX 函数在哪" |
| **数据清洗/转换** | 重复劳动，本地够快 | CSV 清洗、JSON 格式化、正则替换 |
| **简单分类/打标签** | 不需要强推理 | 给 100 条消息分类、提取关键词 |

### 3.2 必须走云端的任务

| 任务类型 | 原因 |
|----------|------|
| **人设对话/聊天** | 云端模型拟人化更好，且用户明确要求聊天走云端 |
| **复杂推理/数学** | 27B 量化模型推理能力不如云端大模型 |
| **创意写作** | 云端模型文采更好 |
| **工具调用决策** | 主模型自己决定调什么工具 |
| **多轮复杂任务** | 需要强规划能力 |

### 3.3 调度逻辑（两层）

**第一层：规则预判（零成本）**
- 请求里包含"批量/所有/全部/整理/转换"等关键词 → 直接走本地
- 请求是纯聊天（问候、情感交流）→ 直接走云端
- 不确定 → 进入第二层

**第二层：主模型判断（消耗少量 token）**
- 主模型看到用户请求后，通过 function calling 决定：
  - 直接回答（云端）
  - 调用 `local_model` 工具（把任务派给本地）
- 工具参数：`task_type`、`prompt`、`max_tokens`

### 4.3 调用流程

```

  │
  ▼

  │
  ▼

  │
  ▼
Ollama 本地推理（~50t/s）
  │
  ▼
返回结果（脚本代码）→ 主模型 → 格式化后回复用户
```

## 五、上下文管理

### 5.1 本地模型独立上下文

- 本地模型有自己的 32K 上下文，**不与主模型共享**
- 主模型只看到：任务描述 + 本地模型返回的结果
- 本地模型的思考过程不回传，节省主模型 token

### 5.2 大文件处理策略

- 文件 > 10K token：本地模型自己做分片处理
- 处理方式：按段落/章节切片，逐片处理，最后合并结果
- 合并逻辑在 local_llm 模块里实现

### 5.3 客户端上下文用量显示

- 客户端顶部显示**两个小圆圈**：
  - 云端主模型：当前会话 token / 上限（如 128K）
  - 本地模型：当前任务 token / 32K
- 本地模型的圆圈只在混合模式开启且有任务时显示

## 六、开关与显存管理

### 6.1 客户端开关

```
设置 → 混合模式
├── [开关] 启用混合模式
├── 本地模型地址：http://127.0.0.1:11434
├── 模型名称：qwen3.8:27b
├── 上下文大小：32768
├── 任务类型白名单：
│   ☑ 批量文件处理
│   ☑ 代码生成
│   ☑ 长文本摘要
│   ☑ 数据清洗
│   ☐ 本地文件问答（需要额外配置）
└── [高级] 空闲 N 分钟后卸载模型释放显存
```

### 6.2 显存管理

- **Ollama 默认行为**：模型加载后常驻显存，直到 `OLLAMA_KEEP_ALIVE` 超时（默认 5 分钟）
- **混合模式关闭时**：
  - 可选：调用 `ollama stop qwen3.8:27b` 立即卸载
  - 或等待 keep_alive 超时自动卸载
- **混合模式开启时**：
  - 模型常驻显存（~10-14GB），随时可用
  - 9070XT 16GB 够用，剩余 2-6GB 给其他应用

### 6.3 配置存储

- 混合模式配置存在客户端 `config.json` 里
- 同步到云端（换电脑也能用）
- brain 启动时读取配置，决定是否注册 `local_model` 工具

## 七、实现步骤

### P0 — 基础打通（1-2 天）

1. **新增 `brain/local_llm.py`**：封装 Ollama API，实现 chat/is_available/estimate_tokens
2. **注册 `local_model` 工具**：加到主模型的 function calling 列表里
3. **工具执行逻辑**：主模型调用 local_model 时，brain 转发给 Ollama，结果返回主模型
4. **客户端开关**：设置页加混合模式开关，关闭时 brain 不注册 local_model 工具

**验收**：客户端开启混合模式后，说"帮我写个 Python 脚本..."，主模型会调用 local_model 工具，本地模型生成代码。

### P1 — 策略优化（2-3 天）

5. **规则预判层**：在 brain 里加关键词匹配，明显的本地任务直接走本地，不浪费主模型 token
6. **结果截断与格式化**：本地模型返回结果过长时自动截断/摘要，避免撑爆主模型上下文

8. **任务白名单**：客户端可配置哪些任务类型允许走本地

### P2 — 可视化与体验（1-2 天）

9. **上下文用量圆圈**：客户端顶部显示云端/本地两个 token 用量圆圈

11. **任务历史**：显示哪些任务走了本地、哪些走了云端，各消耗多少 token

### P3 — 高级功能（可选）

12. **本地模型流式输出**：本地模型推理时实时显示输出（类似主模型的打字机效果）
13. **多本地模型支持**：可配置多个本地模型（如一个代码专用、一个摘要专用）
14. **本地模型微调/LoRA**：后续可以训练专用模型

## 八、Token 消耗估算

### 纯云端模式

- 每轮对话：输入 ~500-2000 token + 输出 ~200-800 token
- 批量文件处理：输入可能上万 token，费用高

### 混合模式

- 主模型多一次工具调用判断：~50-100 token（可忽略）
- 本地任务：**0 云端 token**（本地模型不花钱）
- 主模型只看到本地返回的结果：~500-2000 token

**节省效果**：批量处理类任务节省 70-90% 云端 token。

## 九、风险与应对

| 风险 | 应对 |
|------|------|
| 本地模型输出质量差 | 任务白名单只放简单任务；结果由主模型审核/润色 |
| Ollama 没启动 | 自动降级云端 + 提示用户启动 Ollama |
| 本地模型推理慢 | 显示进度；超时降级云端 |
| 显存不够（同时跑游戏+模型） | 配置空闲自动卸载；或手动开关 |
| 主模型不会主动调用工具 | 系统提示词里强调：批量/代码/摘要类任务优先用 local_model |
