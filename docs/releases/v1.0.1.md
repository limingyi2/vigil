# Vigil v1.0.1 — 2026-10-15

本次发布修复模型设置切换、页面返回和本地工具连接，并整合 Codex 登录检测、Reasoning Summary 与 Agent Timeline。云端 Brain、本机安装客户端和配置指定的本地 Brain 已更新。源代码构建基线为 `8a401b292d48141d1d04ed6cef7e660ac5c3855b`；后续发布提交只添加验收文档及普通合并历史。

## 已完成

- 保留 dev 的 Codex 登录检测、原生 CLI 发现和自动连接修复。
- 合并 `codex/fix-model-settings-cloud-switch`：云端/本机切换、异步请求过期保护、加载错误/超时提示、Agent 详情返回恢复、删除重复 Agent 列表入口、本地工具使用 sidecar 实际端口。
- 合并 `feature/codex-reasoning-summary`：保存发布的 summary，Timeline 折叠展示、状态变化、工具开始/完成和耗时。排除完整 reasoning chain，保留任务与审批安全边界。
- 客户端版本统一为 `1.0.1`、更新 code `18`，生成 Windows NSIS 安装包及便携包。
- 云端 VigilBrain、VigilAgent 运行时限取消，失败后每分钟重试、最多 3 次。新增每分钟健康守护：Brain 连续三次探活失败后重启；Agent 正常退出后启动；显式禁用的任务不被重新开启。

## 部署与恢复

- 云端源码位于 `C:/Vigil`，按已跟踪代码白名单更新；配置、数据、凭据和第三方运行文件保留。部署前备份：`C:/Vigil/_backups/v101-source-20261015-132746.zip`。
- 云端源码清单：`C:/Vigil/release-manifest.json`。健康入口是 `/api/health`。
- 云端健康守护源文件为 `scripts/cloud_watchdog.ps1`，部署到 `C:/Vigil/_backups/cloud_watchdog.ps1`，由 SYSTEM 任务 `VigilHealthWatchdog` 每分钟运行；并发策略 IgnoreNew，执行时限一分钟。
- 本机安装目录 `F:/vigil`；app.asar 旧版备份在 `F:/vigil/backup-v100-20261015`。
- 此电脑配置指定 sidecar 在 `F:/Vigil/dist/vigil-brain`，因此更新了该实际运行位置。exe 备份为 `vigil-brain.exe.v100-backup`，依赖备份为 `_internal-v100-backup-20261015`，插件备份为 `plugins-backup-v100-20261015`。未替换模型配置和用户数据。
- 回滚时先停止对应客户端或计划任务，并暂停健康守护，恢复备份的程序/插件，再启动与探活。不要用旧程序覆盖真实配置；不要在服务运行中直接覆盖文件。
- 新电脑使用本次 NSIS 安装包；已有自定义 `sidecar_exe` 配置的电脑，应单独核对其指向位置，安装新版客户端不会自动改写自定义路径。

## 保留的限制

- 外部 Codex 桌面会话仍仅可读历史；不伪造实时状态。DeepSeek Harness / Work Buddy 仍未接入。
- 真实 CLI 的 `item/commandExecution/requestApproval` 探测返回了不满足现有完整风险/权限条件的请求，`response_enabled=false`；本次未发送审批响应，也未放宽审批逻辑。这类请求保持只读并可中断任务，不能声称全部原生审批已完成端到端验收。
- 完整风险信息的支持类型仍由既有测试验证；额外权限/不完整请求的产品接入需要单独设计和审查。
- 图片理解受配置模型能力限制；视频采用已有 FFmpeg 抽帧，PDF 为有限文本摘录，并非完整视频理解或 OCR。此轮验证上传、提取与失败行为，不宣称所有模型的语义识别质量均通过。
- 健康守护可处理 HTTP 无响应和任务退出，但不能检测每一种业务死锁；没有故意终止生产服务来模拟长期故障。
- 私有仓库历史凭据清理仍按此前要求延期。本次没有改变仓库可见性、重写历史或轮换凭据。
- 后续新分支 `feature/codex-timeline-completion`、`feature/refresh-resilient-stream` 未纳入此次稳定性发布，避免扩大本次验收范围。
