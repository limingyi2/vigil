# Brain 插件市场：当前配置与发布状态

## 当前运行方式

Brain 插件市场不是直接从远端下载并执行插件。Brain 从运行目录的 `config/config.json` 读取 `market_repo`，从该本地 Git 工作副本读取根目录的 `market.json`；插件安装时从清单指定的仓库相对目录复制到 Brain 插件目录，再使用现有静态结构校验和安装事务。刷新操作在已配置仓库中执行 `git pull --ff-only`，成功后重新读取 `market.json`。

Windows 安装版 Brain 的运行根目录由其 sidecar `paths.ROOT` 决定：冻结运行时是 `vigil-brain.exe` 所在目录。因此设置 `market_repo` 的配置文件为该运行根目录下的 `config/config.json`。相对 `market_repo` 路径相对于这个 `config/` 目录解析。未配置时不使用开发机绝对路径；本地插件与普通聊天不依赖插件市场。

市场页分别显示：

- **尚未配置本地插件市场仓库**：`market_repo` 未填写。
- **市场仓库读取失败**：路径不存在、缺少 `market.json`、JSON 结构无效，或刷新失败。
- **市场仓库可用，但没有已发布插件**：读取成功且 `plugins` 数组为空。
- 清单有效并包含插件时显示插件卡片。

安装仍限于用户配置的本地仓库与现有安装器校验。不要仅凭 Manifest、哈希或签名认定第三方插件安全；当前阶段未开放从任意远端自动安装。

## 远端仓库审计（2026-10-19）

GitHub 上存在 `limingyi2/vigil-plugins` 公共仓库，主分支根目录包含 `market.json` 和 `plugins/wallpaper/`。可见的清单只有一个 `wallpaper` 条目，其目录是传统 Brain Python 插件结构；它不是新的 Wallpaper 桌面扩展包，不能据此作为桌面扩展安装。仓库 README 描述了手动提交与推送步骤，但没有看到可核验的自动构建、发布工件、哈希或签名流程。Vigil Core 仓库没有跟踪该市场仓库副本，也没有 `market.json`；Windows 安装包因此不携带开发机的 `F:\vigil-plugins` 路径或市场清单。

由于插件安装会把 Python 代码放入 Brain 插件目录，不应把远端清单视为已通过安全审查的分发源。要使用市场，管理员需要自行配置一个可信的本地仓库副本，并在审阅后安装条目。该审计没有连接或克隆远端仓库，没有安装远端代码。

## 配置示例

在用户实际使用的 `config/config.json` 中加入本地仓库路径，例如：

```json
{
  "market_repo": "D:/VigilPluginMarket"
}
```

不要用这个片段覆盖原配置文件；保留原有字段，只合并 `market_repo`。也可以填写相对于 `config/` 目录的路径。市场仓库需是已初始化的 Git 工作副本，并在根目录提供结构正确的 `market.json`。路径和仓库均由用户自行准备；Vigil 不会自动克隆或保存 Git 凭据。

## `market.json` 最小结构

```json
{
  "version": "1",
  "updated": "2026-10-19",
  "plugins": []
}
```

插件条目的 `path` 必须是仓库内相对路径，安装器会继续执行路径穿越、符号链接和插件结构校验。插件 UI 的名称、描述和版本来自清单；`readme` 等展示元数据不是安装安全边界。

## 功能边界

桌面 Wallpaper 扩展通过“设置 → 桌面扩展”管理，和 Brain 插件市场是两条独立交付链。WeChat Bridge 也不由 Brain 插件市场安装。Brain Python 插件可直接放入 `brain/plugins/`；市场管理只是该插件类型的一种可选来源。
