## 一、定位

Vigil 桌面客户端是一台**控制台 + 常驻代理**，不顶替任何聊天渠道：

- **聊天/管理面板**：和"她"对话（pc 分区）、看数据、管理人设记忆、管设备权限；
- **本地大脑宿主**：把 vigil-brain.exe（PyInstaller 打包的 brain/）当子进程养，PC 渠道的对话、记忆、人设都落本地；
- **本地操控执行器**：微信/App 渠道的大脑把"看看桌面、删个文件"这类活派给这台电脑，客户端领活、执行、回结果；
- **常驻后台**（2026-10-09 起）：点关闭只是隐藏进托盘，进程活着——微信渠道的本地工具轮询、M3 转发通道都不会因为"点了 ✕"而断。

## 三、技术栈（实际在用的）

| 层 | 技术 | 说明 |
|----|------|------|
| 桌面框架 | Electron 28 | `app.disableHardwareAcceleration()` + `disable-gpu` + `disable-gpu-compositing` 三重软渲染（AMD 驱动崩溃防御，db4d789） |
| UI | 原生 JS + 单 CSS | 无 React/构建链，`src/index.html` 直载 `src/js/*` |
| 主渲染通信 | IPC + preload 白名单 | `contextIsolation:true, sandbox:true, nodeIntegration:false` |
| token 存储 | keytar（钥匙串）+ token.json 双写 | 读侧钥匙串优先，两边**都写**防漂（10-09 的 401 事故教训） |
| 本地大脑 | PyInstaller exe（sidecar） | 端口自选，stdout 发 `VIGIL_BRAIN_READY port=N` 就绪行 |
| 云端通信 | HTTP REST + SSE | 主进程统一加鉴权头，渲染层拿不到 token |
| 本地操控 | HTTP 轮询（1.5s） | 不用 WebSocket：服务端零依赖、隧道不用改、出问题两个请求看清 |
| 打包 | electron-builder 24 | NSIS 安装包 + portable + win-unpacked |

## 五、主进程模块详解

### 5.1 main.js

**启动链**：`requestSingleInstanceLock` → `whenReady` → 关系统菜单（自绘标题栏）→ `oplog.init` → `sidecar.maybeStart` → `createWindow` → **`createTray`**（10-09 新增）→ `startPolling`。

**窗口**：1380×880，`frame:false`（标题栏页面自画），`show:false` 等 `ready-to-show`；3.5s 强制 show 兜底（GPU 崩溃机器上 renderer 可能永远不发 ready-to-show）。

**托盘常驻（2026-10-09 新增，用户要求"点关闭隐藏"）**：

- `win.on('close')` 拦截：`quitting === false` 时 `preventDefault()` + `win.hide()`——窗口藏起来，进程活着；
- 托盘单击 = 显示/隐藏切换；右键菜单 = 显示主界面 / **退出**；
- 真退出只走托盘"退出"（先 `quitting = true` 再 close）和系统关机（`before-quit` 统一放行）；
- 不拦的话 `window-all-closed → app.quit()` 会把本地工具轮询、转发通道全带走。

**配置**：`userData/config.json`（地址、device_id、sidecar、forward、sync、localAuto 等非机密）+ 钥匙串/token.json（token 双写）。

**HTTP 代理**：渲染层所有请求走 `ipcMain.handle('api')`，主进程统一加 `Authorization: Bearer`；`/api/chat/stream` 走 SSE（`requestStream`），事件逐块 `webContents.send('api:stream:event')`。带 `src=pc` 的路径自动补渠道参数（服务端按 src 分区）。

**设备注册**：`autoConnect()` 依次探测 本地sidecar → `cfg.base` → `127.0.0.1:18787` → `127.0.0.1:8788`，用免鉴权的 `/api/panel/connect-config`（只认回环）拿主人钥匙 → `/api/device/register` 换**设备 token**（可单独吊销）；已有设备 token 先验后用，不重复注册。

**本地操控轮询（双队列）**：`pollOnce()` 每 1.5s 一轮——本地大脑领一遍活，云端大脑（配了 `sync.cloud_url/cloud_token` 才启）再领一遍。**必须双轮询**：微信消息打到云端，工具调用入云端队列，只轮本地的话"在微信里说帮我看桌面"永远没人领。三档 risk：`safe` 直执行、`confirm` 弹确认、`dangerous` 强确认；`localAuto` 开了自动模式也不免系统目录硬拦。60s 无人应答 = 拒绝。每个动作落 `oplog`（带备份的可在工具页一键撤销）。

### 5.2 sidecar.js（本地大脑宿主）

找 exe 顺序：**配置 > 环境变量 > 打包资源 > 开发仓 `F:\Vigil\dist\vigil-brain\`**。spawn 后从 stdout 抓 `VIGIL_BRAIN_READY port=N`；崩溃自动重启最多 3 次（稳定 10 分钟清零）；应用退出 `taskkill /T` 带走子进程。大脑的 config/data 落在 **exe 旁边**（`paths.py` 冻结模式 ROOT=exe 目录），即 `dist\vigil-brain\config|data\`。

### 5.3 localtool.js（本地工具）

20 个工具，四组：`system`（系统信息/进程列表/活动窗口）、`files`（列/读/找/grep/最近文件）、`clip`（剪贴板读写）、`net`（开链接/截图）、`do`（写/追加/建目录/移动/复制/删除/杀进程/执行命令，全部 danger）。危险集 `DANGER` + 服务端 risk 字段双保险；写类操作自动做备份（`oplog` 记 backup 引用，`local:undo` 还原）。

### 5.4 forward.js（M3 双大脑转发）

云端 `/api/chat` 拦截器把**本地操控类**请求转给这台电脑的本地大脑。启动条件：本地大脑 ready + 云地址已知（`cloud_base` 或非回环的 `cfg.base`）+ `cfg.forward !== false`。sidecar 每次 ready 自动重启转发。

## 六、渲染层

- 无框架、无构建链：`index.html` 直载 `js/app.js → api.js → ui.js → pages.js`；
- 导航：`app.js` 的 `go(page)`，`PAGES` 注册表（pages.js 末尾）——`chat / data / persona / ability / system` 五页；
- 聊天页：SSE 流式渲染（思考过程 + 正文逐块）；**已知缺口**：`ui.js` 的 `inline()/md()` 还不认 `[img:NAME]` 斗图标记（微信历史里会显示标记原文，重打包清单①）；
- 数据页：`/api/stats` 打的是**所连的大脑**——PC 客户端连本地 sidecar 时看到的是 pc/app 分区的账，微信渠道的量在云端（重打包清单②：云端视角切换）；
- 人设页（persona）：渠道人设绑定（persona_by_src）+ 人设编辑；记忆页能力并入 persona/工作台（M5）；
- 系统页（system）：连接与设备（token/设备列表/重绑）、模型与接口（向导走 `/api/models` + `/api/models/apply`，无写死列表）、云端同步子页（M5：开关/状态/立即同步/凭据）、权限菜单（localAuto 三档）。

## 七、渠道与大脑拓扑（谁的话在哪处理）

| 渠道 | 处理大脑 | 人设绑定（persona_by_src） | 历史/记忆分区 |
|------|---------|---------------------------|--------------|
| 微信私聊（src=wechat） | **云端** 8788 | `default`（老吴猫，2026-10-09 定） | default.wechat.* |
| 微信群（src=wechat_group） | **云端** 8788 | `default`（同上） | default.wechat_group.* |
| PC 客户端（src=pc） | 本地 sidecar | `pc_assistant` | pc_assistant.pc.* |
| 手机 App（src=app） | 云端 | 全局 persona_file | *.app.* |

- **绑定只认云端 config.json**（`runtime.py` 的 CFG_PATH → `C:\Vigil\config\config.json`）。App 里改绑定写的是本地 config，10-09 之前**不同步**——这就是"App 里设了人设、微信里不生效"的根因；已修：`persona_by_src` 加入 M2 behavior 同步段（`sync_client.py`），随下次重打包生效；
- 10-09 还发现**同名不同货**：云端 `default.json` 里装的是"八奈見杏菜"，本地才是老吴猫——已把本地（用户在 App 里看到的那份）推上云端，备份 `.bak_catpush_20261009`；
- 人设文件 `label` 字段是 App 下拉里显示的名字：`default.json` 现在两侧都标了 `老吴猫`，防止"default 看着像默认人设其实是只猫"的坑。

## 八、打包与发版

- `npm run dist` = `electron-builder --win`：NSIS 安装包 + portable + win-unpacked；
- `asarUnpack: keytar`（原生模块必须解包）；
- **本机构建注意**：WorkBuddy 沙箱有批量删除保护（一次删 >50 个文件要确认），electron-builder 清空旧 `dist/win-unpacked` 会被拦——所以本次产物在 **`dist_new/`**；以后要么先手动分批清产物，要么固定换新输出目录（`-c.directories.output=dist_new2`）；
- 构建完交付：`dist_new\Vigil Setup 0.1.0.exe`（安装版）或 `dist_new\Vigil 0.1.0.exe`（便携版）；当前运行中的旧版没有托盘行为，装新版后生效；
- 本地大脑 exe 的放置：`F:\Vigil\dist\vigil-brain\vigil-brain.exe`（sidecar 的"开发仓 dist/"查找规则会找到它）。
