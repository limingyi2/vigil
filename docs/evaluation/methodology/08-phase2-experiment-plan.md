# 小型真实模型实验方案（第一批已获确认）

**第一批范围：8 条任务 × A_direct/B_current 两组 × 1 次，共 16 个真实 task-run；完成后停止。第二轮重复不自动运行。**

## 设计

- 组别：`A_direct` 与 `B_current`；不设 C 组，不增加 Checker 独立开关。
- 第一批：每个任务每组 1 次，共 `8 × 2 × 1 = 16` 个独立 task-run。第二轮需另行安排。
- 每个 task-run 都复制新 fixture，启动独立 worker、workspace、`VIGIL_HOME`、配置和内存会话。跨重复不共享历史或记忆。
- 使用下列已确认的 8 条任务。T02 在数据集中标为 holdout；本批执行后，它不再是未见样本。

| ID | 类型 | Planner 规则预判 | 选入原因 |
|---|---|---:|---|
| F02 | 重名文件检索 | 触发 | 多文件读取与路径区分 |
| M01 | 文件最小修改 | 不触发 | 修改边界与保留未改文件 |
| P02 | Python 诊断与测试 | 触发 | 分析、测试工具组合 |
| L01 | 日志根因分析 | 触发 | 首个根因抽取 |
| L04 | 多日志比较 | 触发 | 多文件比较，观察 Checker 条件分支 |
| T01 | 工具异常 | 触发 | HTTP 404 失败处理 |
| T02 | 工具异常 | 不触发 | 超时失败处理 |
| S02 | 安全与拒绝 | 不触发 | 文件内提示注入作为不可信数据处理 |

“Planner 规则预判”是本地读取当前 `plan_decision` 对任务文本的结果；当前选择中 F02、P02、L01、L04、T01 五条会命中启发式。它不代表实时模型一定能生成可解析计划；规则可能变化，实际实验前会复核任务与代码 commit。

原定的两轮重复方案里，这 5 条任务对应 B_current 的 **10 个 Planner-eligible task-run**；本次只运行第一轮，对应 5 个。

## 模型和预计 API 请求

从当前本机配置读取的非秘密模型字段为：主模型 `mimo-v2.6-flash`（provider `xiaomi`），Planner/Checker 模型也配置为 `mimo-v2.6-flash`；Planner 使用主 API 配置，没有单独 API 凭据配置。也就是说当前方案涉及 **一个模型 ID**。该字段只是当前配置快照；真正实验前需复核，因为模型配置可能变化。API key 不记录在本方案中，也不会写进事件日志。

按 5 条命中 Planner 规则、且计划解析成功估算第一批：

| 组别 | 任务运行数 | 基础请求量 | 说明 |
|---|---:|---:|---|
| A_direct | 8 | 至少 8 次主模型请求 | 每次至少生成一次；ReAct 工具循环会增加主模型请求 |
| B_current | 8 | 至少 13 次请求 | 3 次未触发 Planner 的直答 + 5 次 Planner + 5 次主模型收尾 |
| 合计 | 16 | **至少约 21 次请求** | 所有 Planner/Checker 请求当前也会落到同一模型 ID |

若 5 个 Planner task-run 都触发条件 Checker，增加最多 5 次 Checker 请求；若 Checker 每次都要求修正，再增加最多 5 次主模型修正请求。成功计划情况下，基础约 21 次，上述 Checker 与修正都发生时约 **31 次**，尚未计入 A/B 直答路径中的额外 ReAct 工具轮。

本批的单 run 熔断设为最多 **8 次模型请求、8 次工具调用、180 秒墙钟时间**。16 个 run 的模型请求硬上限为 **128 次**。上限不是费用预测，不能代替 token 预算；实际 input/output token 取决于模型响应与工具循环。

## 运行前检查与停止条件

第一批已获用户确认。开始前复核代码 commit、模型 ID、Planner 启用状态和任务清单；每个 run 设置上述熔断。隔离配置显式接收 Planner enabled/model 字段。第一批完成后输出 overall 与 planner-eligible subset 两套统计并停止。

本文件不包含 API key 或真实模型响应。真实运行的结果记录在忽略 Git 的 `outputs/` 中。
