# 插件系统

加一个新功能只要往 `brain/plugins/` 丢一个文件，核心代码一行不改。

## 为什么做这个

以前加一个功能（比如"闹钟提醒"）要动四个地方：

1. 新建 `alarm.py`
2. 改 `reply.py` —— 加一段"检测到闹钟关键词就调 alarm.py"
3. 改 `server.py` —— 可能加接口
4. 改 `persona_store.py` 的提示词 —— 告诉她有这个新本事

功能多了之后 `reply.py` 变成一堆 if-else，改一个功能可能弄坏别的；
而且第 4 步最容易漏 —— 代码里能力已经加上了，提示词没同步改，
她就根本不知道自己有这个本事（这类 bug 极难查：接口能通、日志正常，
只是她"不用"）。

插件化之后核心只认下面这几个钩子，其余全在插件文件里。

## 核心改了哪几处

一共 6 个文件、每个只加几行，列出来是为了让人知道**去哪儿找**：

| 文件 | 加了什么 |
|---|---|
| `plugin_host.py` | 加载器本体（新文件） |
| `paths.py` | `PLUGINS_DIR` / `PLUGIN_DATA_DIR` 两个常量 |
| `features.py` | `register()` / `invalidate()`，让插件能登记成开关 |
| `tools.py` | `run_tool()` 多问一句插件；`tool_help_extra()` |
| `persona_store.py` | 工具清单里的 `{plugin_tools}` 占位符 |
| `brain.py` | `draft()` 里拼 `plugin_host.prompt_block()` |
| `server.py` | 装载、`on_turn_in`、`on_reply`、`/api/plugins`、插件路由 |

**核心代码里没有任何一处写着"if 插件叫 xxx"** —— 认识具体功能的只有插件自己。

## 一个插件长什么样

```python
NAME = "reminder"        # 必填，插件名（英文/数字/下划线/短横线）
DESC = "闹钟/提醒"        # 必填，给人看的
FEATURE = "reminder"     # 选填，声明后 App 设置页自动多一个开关

def prompt(ctx): ...            # → 拼进 system：告诉她"你有这个本事"
def on_turn_in(ctx): ...        # → 他发消息时，返回要注入 system 的提示
def on_reply(ctx, text): ...    # → 回复加工完（剥标记/生图/语音之后）
def start(brain): ...           # → 自己的后台线程，进程启动时调一次
TOOLS = {"名��": 函数}           # → 模型可以 [tool:名字:参数] 调它
TOOL_HELP = "..."               # → 教模型怎么用，随 tools 一起进提示
ROUTES = [("GET", "/api/plugin/xx", 处理函数)]   # → 自己的 HTTP 接口
```

钩子全都是可选的，写哪个算哪个。

### 钩子各自拿到什么

`ctx` 是一个 `Turn` 对象：

| 字段/方法 | 说明 |
|---|---|
| `ctx.text` | 他这一轮说的话 |
| `ctx.src` | 渠道：`app` / `wechat` |
| `ctx.api_config` | 共享的 API_CFG（要读模型/key 从这儿拿） |
| `ctx.brain` | 大脑对象。**只读用** —— 问问题、查记忆可以，别改内部状态 |
| `ctx.meta` | 插件自己的中途数据，同一轮内各插件共用 |
| `ctx.say(text)` | 让插件主动开口（走主动搭话那条路，App 会弹通知） |
| `ctx.ask(prompt)` | 借她的嘴说一句（记忆/生活/摘要都会正常走一遍） |
| `ctx.data_dir()` | 插件自己的持久化目录 |

`on_reply` 多一个参数：`(ctx, text) -> str`。**必须返回字符串**，想不动就原样返回。

## 三条纪律

### 1. 插件坏了不能拖累她

每个钩子都单独 try/except，炸了只打印一行（带插件名），`on_reply` 出错就返回原文。
进程内没法真正隔离 import 副作用，所以**插件里禁止在模块顶层做网络请求** ——
要用就在钩子里调。

### 2. 提示词只写"有什么、各是什么"，不写"什么场景必须用"

这条是刻意的。以前 `persona_store` 里那种"他问「我在哪」→ 用 ip_city；
他问天气 → weather" 的映射，每加一个场景就得补一条规则，永远补不完；
而且漏补的那条不是"她忘了用"，是"她压根不知道有这功能"。

对比一下 `reminder` 的 `TOOL_HELP` 写法：

```
- 提醒（闹钟）：[tool:reminder_set:他说的原话] 设一个到点主动提醒他的事
  （支持「20分钟后」「明天早上八点」「八点半」「三天后」）；...
  设了提醒她真的会到点主动喊他，所以只要他说了任何带时间、像是
  「待会儿/回头/到时候/别忘了」的事，就设上 —— 他自己不记这个。
  提醒已经设过、到了、或者他说的不是时间（比如“明天见”这种约见面），
  就别重复设。
```

给的是**能力清单 + 判断依据**，不是场景映射表。她自己判断什么时候用。
（唯一保留的场景提示是"别把'明天见'当提醒"这种**反例** ——
告诉边界比列场景省事，也不会漏。）

### 3. 工具名不认识就是不认识

`run_tool` 查不到就返回 None，她照实说"查不到"。
模型编出来的工具名（比如 `[tool:天马行空:xxx]`）由 `tools.TOOL_TAG_ANY_RE`
兜底扫掉，不会原样漏到用户眼前 —— 这条在插件化之前就有，插件工具同样受管。

## 开关

声明了 `FEATURE` 的插件自动出现在 App 设置页（`/api/features`），
默认开，关掉后：

- `prompt` 不再拼进提示词
- `on_turn_in` / `on_reply` 不再被调
- 它的工具调不通（`run_tool` 返回 None）

没声明 `FEATURE` 的插件**永远开**。想让它能被关掉就声明一个，
别自己在钩子里读 `config.json` 判开关 —— 那等于把白名单又写死一遍。

## HTTP 接口

| 路由 | 作用 |
|---|---|
| `GET /api/plugins` | 插件清单 + 管理视图（见下） |
| `POST /api/plugins/reload` | 重扫目录重装。返回 `restart_needed` |
| `POST /api/plugins/install` | 装插件包。body `{"zip_b64": "<base64>"}` |
| `POST /api/plugins/uninstall` | 卸插件。body `{"name":..., "purge_data":false}` |
| `POST /api/plugins/channels` | 改渠道。body `{"name":..., "channels":["app","wechat"]}` |
| `/api/plugin/<名字>` | 插件自己声明的（`ROUTES`） |

`GET /api/plugins` 返回两个键：

- `plugins` —— 老的形状，**别改**。微信桥接（`wxauto_bridge.pick`）和
  VM 启动器（`zx_launcher.py`）拿这个接口当"大脑活着吗"的探针，
  只看 HTTP 200，但也别哪天为了面板好看把它删了。
- `manage` —— 给面板的：`{channels: [...], items: [...]}`，
  一次给全，页面不用等好几轮才填满。

`/api/plugins/reload` **不会重启已经起了的后台线程**（线程无法二次启动），
所以带 `start` 钩子的插件改完要重启大脑 —— 返回里的 `restart_needed`
就是提醒这件事。它会顺手 `reload_persona()`，好让新插件的工具说明进提示词。

## 插件管理面（面板）

`admin/dashboard.html` 的「插件管理」页：拖 zip 装、卸、每个插件选渠道。
前端只认 `manage.items` 里这些字段：`name` `desc` `feature` `tools` `routes`
`hooks` `file` `err` `channels` `channelable` `meta`。

### 为什么管理面是独立的 `plugin_ops.py`

`plugin_host` 是**加载面**（每轮聊天都在走，必须极稳），
`plugin_ops` 是**管理面**（装卸时可以随便加功能）。分开的三个理由：

1. 装插件 = 往云服务器上传代码（等价于远程执行入口），这块的校验规则
   变化频繁，不该和"怎么派发钩子"混在一个文件里互相牵连
2. 加载面多一个字节的抖动就是聊天挂掉
3. 内核零改动 —— `plugin_host` 一行没动，唯一交点是装完调 `load()`

### 渠道开关复用 `features_by_src`，不新造字段

插件在哪些渠道生效，写的就是已有的 `features_by_src.<渠道>.<FEATURE>`，
**没有** `plugin_channels` 这种新结构。理由：功能此刻开没开已经有唯一答案
（在 `features.on(key, src)`），再造一份就必然出现两处不一致 ——
而"界面关了、实际还开着"是最难查的一类 bug。

`set_channels` 对**每个渠道都显式写值**（包括 false）。只写勾上的那些不行：
插件装之前全局是 true，取消勾选就变成"没写 = 跟全局走 = 还开着"。

界面上的渠道多选**不复用顶栏那个 App/微信切换器**：顶栏是"我现在看哪边"，
这里是"这个插件在哪些边开着"，两件事。而且"两个都开"是最常见的一档，
跟着顶栏走根本没法表达。

### zip 只收"单一形状"

`inspect_zip` 只接受：**一个 `.py`**（插件本体）+ 可选 `zxplugin.json` /
`.md` / `.txt`（附属文件）。所以这些一个都不用逐个堵：

- 路径穿越（`../`）、绝对路径、盘符、`\`/`/` 混用
- NTFS ADS（`evil.py:hidden`）
- zip 炸弹（解压后 16MB / 单文件 2MB / 文件数 64 三道上限）

**目录包明确拒绝**，理由是"装得上但跑不起来"是最坏的失败方式 ——
`plugin_host.load()` 只扫 `*.py`，压成目录装上去插件也不会生效，
用户只会看到"安装成功"然后功能没有。

硬边界在 `plugin_ops.py` 顶部常量里，改的时候记得连带测试
（`_test_plugin_install.py`，83 项）一起改。

### 元数据不进 .py

作者、版本、安装时间写 `plugins/_registry.json`。这个文件**可丢弃** ——
丢了只是界面少显示几行字，`overview()` 会兜住，插件照跑。
往 `.py` 里塞元数据就得改插件自己的代码，插件是别人写的。

## 持久化

放 `data/plugins/<插件名>/`，插件自己管文件。`ctx.data_dir()` 返回这个目录
（不存在会建好）。这个目录**不归 `paths.ensure()` 管**，
插件自己 `makedirs` 就行。

## 已有的三个插件

### `reminder.py` — 闹钟/提醒

他说"20分钟后叫我起床"就真的到点主动喊他。

- `TOOLS`：`reminder_set` / `reminder_list` / `reminder_cancel`
- `on_turn_in`：他发消息时把"手上还有哪些到点要喊的事"喂进上下文
  （不这么做的话，他说完"20分钟后叫我"又去聊别的，她就不记得该喊他了）
- `start`：10 秒一轮的线程，到点借她的嘴说一句
- 数据：`data/plugins/reminder/reminders.json`

支持「20分钟后」「十分钟后」「半个钟头后」「三天后」「明天早上八点」
「八点半」。**单位参与换算**（"三天"≠"三分钟"，这个错犯过）。

### `calc.py` — 算数

纯 Python 的四则运算，零延迟零成本。她心算三位数乘法就出错，
而他要对账的数错了比不算更糟。

`eval` 之前有白名单：只留数字和 `+-*/().`，`__import__` 这类一律拒。
`{expr: "builtins": {}}` 之外还有 `re.fullmatch` 兜底，两道都要。

### `websearch.py` — 联网搜索

接 [AnySearch](https://www.anysearch.com/docs)（面向 Agent 的结构化搜索服务），
一个 `POST /v1/search` 跨多类信源检索，返回 `title/url/snippet/content`。
实测云端（杭州 2C2G）直连可用，1.5~2.7s，中英文都行。

- `TOOLS`：`search`
- `FEATURE`：`websearch`（App 设置页可关）
- 免 API key 就有免费额度；填 `config.json` 的 `search.anysearch_key` 走付费额度
- `ROUTES`：`/api/plugin/websearch?q=...`（调试用）
- 结果缓存 30 分钟，同一个问题不打两次网络

**领域由她自己选，不做关键词映射。** 可选项只写进 `TOOL_HELP` 给她看
（`[信源:code]` `[类型:news]` `[新鲜度:week]` `[区域:cn]` `[条数:6]`），
代码里不判断"什么话题该走哪个域"—— 那种映射加一个场景就得补一条，
而且模型被管死了就不会自己判断。非法值服务端会静默忽略并回落通用搜索，
所以她自己选错也不会把搜索搞坏。

#### 写联网工具的坑：她会说"等我查查"然后什么都不做

工具跑通了、提示词也进去了，但她回一句「你等我搜搜看」就结束 ——
用户看到的是**答应了却不干活**。四轮改下来摸到的规矩：

1. `TOOL_HELP` 里**必须重复核心那句"只写一行标签，别的都不说"**。
   核心规则里那句紧挨着 `[tool:weather]`，weather 一直能触发；
   插件说明写成另起一段的散文时，模型读成了"她会的本事"而不是
   "必须输出的调用格式"，于是选择用嘴代替标签。
2. **劝阻的话不能写在常驻 `TOOL_HELP` 里。** 写了"别只说不做""别为了显得
   努力什么都搜"，她开始**拿搜索当话来说** —— 回"大半夜的又搜 DeepSeek，
   你是打算自己搞个AI吗"，搜索变成了她吐槽的素材而不是她做的事。
   她的嘴很贫，任何关于"要不要做"的措辞都会被当成可以聊的内容。
3. `on_turn_in` 只给**动作**，不给理由、不留评价空间：
   「这一轮你的回复**只写一行** `[tool:search:他的原话]` ——
   不要提搜索、不要说等他查完、不要评价他问这个干什么。」
   写"你判断一下值得就调"等于给了她不调的许可（实测确实不调）。
4. 触发率目前约 **50%**（问「搜一下X」时）。工具、链路、云端连通性都已验证，
   剩下的是模型与她人设的拉扯，不是代码问题 —— 想提高就往 `on_turn_in`
   的措辞上加压，代价是更容易触发第 2 条。

改完当场用真接口验：`/api/chat` 发"帮我搜一下…"，**看答案里有没有实时数据**。
没有真实数字（股价、温度、版本号）就是没调工具 —— 别看她说得多自然，
她一本正经胡说八道的时候语气跟真的一样。

## 加新插件的步骤

1. 建 `brain/plugins/<名字>.py`，写 `NAME` / `DESC` 和你要用的钩子
2. 要能被 App 关掉就加 `FEATURE = "<名字>"`
3. 想要工具就写 `TOOLS` + `TOOL_HELP`（**别忘了 TOOL_HELP** ——
   没有它模型不知道这个工具存在，就永远不会被调）
4. 本机验：`POST /api/plugins/reload`，再 `GET /api/plugins` 看装上了没
5. 部署（**注意：云端要传到 `C:\Vigil\plugins\`，
   `brain\plugins\` 那份副本不生效** —— 见 MEMORY.md 的"云端有两份代码"）
6. 重启大脑

## 做成分发包给别人装

面板能收 zip，所以插件可以打包发出去。包里的形状（`plugin_ops` 只认这一种）：

```
你的插件名.py          ← 必需，恰好一个 .py
zxplugin.json          ← 可选：{"name","author","version","desc"}
README.md              ← 可选
```

`zxplugin.json` 里的 `name` 用来认插件；没有就用 `.py` 的文件名。
别在包里放第二个 `.py`，会被拒（装进去加载器也只认一个）。
别压成目录（`包名/你的插件名.py`），会被拒。

装完在面板上选渠道即可。想让某个渠道关掉它，`.py` 里必须有 `FEATURE`；
没声明的话面板上那两格是灰的 —— 契约上"永远开"，不给关。
