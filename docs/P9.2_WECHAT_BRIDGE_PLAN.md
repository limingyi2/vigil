# P9.2 · WeChat Bridge 独立运行方案与验收边界

状态：技术方案已建立；本阶段不接入真实微信、不启动 UIA，也不更改 Brain 通用 Persona、记忆或权限策略。

## 1. Bridge 安装与启停

- Bridge 作为独立 Windows x64 包交付，运行在安装了受支持微信桌面版和 UI Automation 依赖的专用用户会话/VM。Core 安装包和 Brain PyInstaller 包不包含 Bridge 源码、运行时或启动器。
- 用户在 Bridge 自己的安装器中安装、升级和卸载。安装采用不可变版本目录、活动版本指针和上一版本回退；数据、凭据和微信登录态不放在程序目录。
- 生命周期由 Bridge 自身服务管理器控制：`installed → stopped → starting → healthy → stopping → stopped`，状态带实例 ID、版本、协议版本和健康检查时间。停止先关闭事件收取，再完成/标记在途事件，关闭 Brain 会话并退出 UIA worker；超时才终止其子进程。
- Core 只显示用户配置的 Bridge 状态和独立安装文档链接，不替用户拉起微信或开始轮询。Brain 只接受显式启用且 scope 有效的 channel credential。

## 2. Bridge 与 Brain 的受限协议

采用版本化本机/网络 HTTP 或 WebSocket 协议，v2 事件使用结构化 envelope：

```json
{
  "protocol": "vigil-channel-bridge/1",
  "bridge_id": "opaque-install-id",
  "event_id": "uuid",
  "channel": "wechat.private",
  "sender": {"handle": "bridge-scoped-pseudonym", "owner": false},
  "message": {"text": "...", "attachments": []},
  "occurred_at": "RFC3339"
}
```

- Brain 为每个 `bridge_id` 颁发 channel-scoped credential。Credential 只允许提交指定 `channel_ids` 的 ingress event；Bridge 不获得插件管理、模型配置、文件系统、本地工具或任意 Brain admin API。
- `event_id` 是幂等键。Brain 先验证协议、凭据 scope、channel、长度、附件类型/大小、时间窗口和重放状态，再交给既有渠道归一化与 Persona/记忆/策略路径。群聊 `sender` 和 `channel` 由 Brain 侧映射表二次核对；不接受客户端自报 owner 授权。
- Ack 明确包含 `accepted | duplicate | rejected`、可重试标志和 request correlation ID。Bridge 使用有界队列、指数退避和死信过期；超时事件不得无限重放。日志不记录 token、原始微信账号标识或完整消息正文。
- 过渡期提供 feature-flag adapter：旧 `/api/chat` 接口映射成同一内部 event contract；按安装逐个切换、支持回退，旧接口退役前必须检查实际调用量和兼容窗口。

## 3. 凭据与访问授权

- Bridge 凭据保存在运行 Windows 账号的 Credential Manager/DPAPI 槽位中；若目标 VM 无可用安全凭据 API，则使用仅该账号 ACL 可读、DPAPI 加密的独立文件。不得使用 Brain `config.json` 回退，不放命令行、URL query、manifest、日志、聊天历史或 Core 普通配置。
- 安装时由用户明确绑定 Brain endpoint 和 channel scope；显示 Bridge ID、channel 列表、过期时间与撤销入口。Core 只持有非秘密的 credential reference 和状态，不读取 secret。
- Brain 支持逐 Bridge 撤销、轮换和短期并行轮换；scope 由服务端记录，不相信 Bridge event 中的 `src` 字段。仅当已有 Brain 的 owner/group 权限检查通过，消息才进入原来的策略执行链。

## 4. 旧配置与数据迁移

- 迁移器只接受显式选择的旧 `wxbridge.local.json` 路径；先复制到加密/受 ACL 保护的 staging，校验字段与目标 Brain，再以新 scoped credential 完成探活。任何一步失败都保留原文件并恢复旧指针。
- 映射 `brain_base`、旧 bridge token、私聊会话名单、群聊名单/触发策略、轮询间隔和媒体限制；旧的全权 `brain_token` 不能原样升级为 Bridge 权限，必须由 Brain 管理端换发 scoped credential。
- 用户会话分类、消息去重状态和待发送队列迁移采用 copy → validate → commit；消息历史和微信登录态留在 Bridge 所在用户配置目录。迁移不删除旧文件，用户确认新版本稳定后可单独归档；日志与迁移报告只记字段名和结果，不记秘密值。
- 迁移需幂等，重复执行不得重复发送事件；支持 `dry-run`、状态校验、恢复旧配置与回退旧 Bridge 版本。

## 5. 无微信插件时 Core 初始化与依赖清理

- Core 启动不得 import `wxauto4`、`pywin32`、UIA、微信 SDK 或 `wechat-bridge` 模块；不得扫描微信登录态、打开微信窗口、建立 Bridge 连接、轮询消息或创建微信线程。
- Brain/Core 包不捆绑 Bridge 源码、微信运行时、Bridge 凭据或微信专用自动启动配置。删除/废弃任何 Core 启动器前先对当前仓库、安装包 spec、服务注册、任务计划、快捷方式和更新脚本做静态清点。
- 清理不能删除通用 `wechat`/`wechat_group` source normalize、Persona/记忆分区、gate、owner 与群聊权限规则、附件通用模型或其它渠道使用的 Bridge RPC。仅移除无插件时专属的初始化、依赖 import 和无调用的启动绑定。
- Brain 的旧兼容 `/api/chat` adapter 暂留在服务端；确认所有旧 Bridge 调用归零并经过至少一个兼容发布周期后，才单独评估退役。

## 6. Fake Bridge 生命周期测试

Fake Bridge 不安装微信、不导入 UIA、不连接真实 Brain、不调用模型、不发送消息。使用随机临时目录、假凭据和 loopback fake Brain，并验证：

1. 安装/校验 → 停止态；启用 → 子进程启动、协议握手与健康检查；禁用 → worker/连接/队列句柄关闭；再次启用 → 新实例恢复。
2. 重启恢复版本、启停意图和用户数据；更新健康检查失败回滚旧版；卸载移除程序目录和 credential reference，数据按保留策略存在。
3. 未安装/停用时无 Bridge 子进程、无 UIA import、无后台连接；异常退出只更新 Bridge 状态，不影响 Core 聊天、模型设置、工作区和其他渠道。
4. Brain 拒绝错误 scope、伪造 channel/sender、超大 payload、无效附件、过期时间和重放 event；合法重复 event 返回 `duplicate` 且业务效果仅一次。
5. 超时、断连、重试上限、队列满、停止时在途事件和迟到 Ack 均有确定状态；凭据轮换期间新旧 credential 按期工作，撤销后旧 credential 必须失败。

Fake 测试通过只证明协议与生命周期，不代表 Windows 微信/UIA、真实账号登录、焦点行为或真实收发通过；这些需要单独的专用隔离 VM 和专用测试会话验收。
