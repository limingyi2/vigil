## 已完成

- 把 Electron 主入口拆为 Core 入口和插件宿主入口。通用插件 UI 由独立 Electron 子进程承载；插件 renderer 使用独立 session、随机认证的本机 IPC、最小 preload 和受限 CSP。
- 在 Electron 28.3.3 实际运行时读取了插件 WebContents preferences：`nodeIntegration=false`、`contextIsolation=true`、`sandbox=true`、`webSecurity=true`；`require`、`process`、`fs` 不可用，Core DOM 不可见，Core 与插件 renderer PID 不同。
- Broker 根据已登记 WebContents 绑定身份，并在每次请求检查插件注册状态、授权、操作及参数。未授权路由、伪造 Wallpaper 身份、路径穿越和 CSP 任意 loopback 资源探测均被拒绝。
- 插件 renderer 崩溃后回收整个隔离 Electron 子进程；Core 保持工作，用户重新打开插件时启动干净宿主。禁用时先撤权、注销页面并回收插件宿主；重新启用后可重新注册。
- Wallpaper 扩展业务入口继续由 utility process 承载；扩展卸载清程序版本目录，保留 `userData/wallpaper-engine` 用户素材和配置。
- 修复旧插件测试夹具没有 `frontend_permissions` 属性导致的兼容性异常；旧夹具现在缺省为空权限。
