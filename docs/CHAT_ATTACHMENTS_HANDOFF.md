# 聊天附件改版交接

## 已完成

- 回形针选择和拖放支持图片、MP4、MOV、WebM、PDF、TXT、Markdown、CSV、JSON。
- 视频在发送前显示原生预览；普通文件显示名称、大小、类型、进度和移除按钮。
- 非图片附件通过 Electron 主进程分块发送到 `/api/attachments/upload`，单块 1 MB，服务端上限 256 MB；聊天 JSON 只携带附件 ID 和脱敏元数据。
- 服务端按扩展名/MIME、大小、连续偏移和安全 ID 校验，文件保存到 `data/upload/attachments`，不接受路径。
- 上传必须经过客户端明确确认；服务端没有确认头会返回 428。
- PDF/TXT/JSON 等附件只提取有限文本；视频不会被伪称为已看过完整内容。当前视频能力接口返回不支持，客户端经确认后最多抽取 3 个浏览器关键帧，并把关键帧作为独立图片附件发送。
- 聊天历史仅保存附件 ID、名称、类型、大小，不保存绝对路径或二进制。

## 快速验证

在 `brain` 目录运行：

```text
python -m unittest tests.test_attachments -v
```

覆盖本地分块视频保存/读取，以及非法类型和非连续分块拒绝。未运行完整 P3/P4/Creator 测试矩阵。

另外用临时 `VIGIL_HOME` 和回环 Brain 做了一次 HTTP 烟测：未带用户确认头返回 428；带确认头的 MP4 两块上传返回完成元数据，随后下载校验字节一致。

## 边界

附件接口沿用现有 Brain Token/设备权限。渲染层的确认用于避免误上传；它不是强真人身份认证。未实现云端视频原生理解，用户必须看到能力提示并确认是否提取少量关键帧。
