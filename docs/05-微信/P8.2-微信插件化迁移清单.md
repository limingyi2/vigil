# P8.2 · WeChat Bridge 插件化迁移清单（历史规划，已由 P9.0 校正）

本文保留 P8.2 交接背景；以下内容是**历史提案，不代表当前已实现能力**。拆分前的兼容与迁移基线以 [P9 扩展协议](../P9_extension_protocol.md)、[P9 数据迁移约定](../P9_data_migration.md) 和当前源码为准。

## 当前已证实的交付边界

- WeChat Bridge 是独立渠道服务；独立公开仓库 `zhixia-wechat-bridge` 是其发行项目源码仓库，Vigil 的 `wechat-bridge/` 是漂移的副本（同名文件 blob 不同）。两处代码的自动镜像/同步规则及生产部署实际引用版本尚未建立或核实。
- `brain/plugins/gate.py` 是当前 Brain 插件宿主使用的实现；`wechat-bridge/brain-plugin/gate.py` 是旧副本，存在语义差异，且没有当前宿主的显式 `Turn.veto()` 用法。不可视为自动同步副本，也不能直接部署到当前 Brain。两份 gate 分属不同交付物；后续需明确版本来源并做行为等价测试。
- 本仓库不存在 `brain/wechat_bot/`。旧文档中的该路径及“部署脚本从那里读取”的说法过期；当前桥接入口在 `wechat-bridge/wxauto_bridge.py`。`deploy/wechat/` 中仍有旧部署路径假设，需后续核对目标环境后才能使用。
- `wechat-bridge/wxauto_bridge.py` 是独立桥接程序，不是 `brain/plugins/*.py` 的 Python 插件。Brain 插件可在 Core/Brain 进程内注册工具、路由或钩子；Bridge 在独立机器/进程持有微信登录态，通过现存 HTTP/WS 接口连接 Brain。
- `brain/ws_forward.py` 是 Brain 侧可选转发能力；`client/electron/forward.js` 当前没有由 Electron `main.js` 启动。双 Brain 转发与 WeChat Bridge 独立、可选，不属于同一个插件。
- 目前没有可据以确认的 Bridge 插件 Manifest、Core 托管生命周期、权限隔离凭据库或自动回滚机制。旧版清单中“加密配置”“复用现有插件市场即可落地”等均为未实现规划，不可作为事实。

## P8.1 记录中需要重新验收的事项

P8.1 关于客户端不自动启动 Bridge/`forward.js` 的结论，应以当前 main-process 调用点为准；当前源码未见 `main.js` 启动 `forward.js`。远端路由、部署脚本、服务端同步状态和生产调用情况不在此静态审计的证明范围内。

`client/src/js/pages.js` 仍可能出现“市场插件”或未来规划文案，与独立 Bridge 方向冲突。按 P9.0 范围，仅在报告中登记；本阶段不修改产品 UI。

## 后续迁移验收（尚未完成）

1. 未安装扩展时，桌面 Core 不启动 Bridge、不创建隐式远端连接；由隔离环境验证进程树和网络行为。
2. 独立 Bridge 只获得已登记渠道的收发与 Brain 对话权限；分别验证私聊 owner、群聊 safe-only 和 remote control 默认关闭。
3. 禁用/卸载 Bridge 后，渠道连接关闭，历史、人格、记忆、权限配置和运行机登录态均保留。
4. `/api/chat`、`msg/ack/result` 与可选双 Brain 转发经适配器进行幂等兼容验证；不得重复发送消息。
5. 所有凭据迁移只在受保护凭据存储之间完成，失败时保留旧配置并可回滚。

以上验收需要 P9.1 及后续批准后实施；本文件不授权真实微信登录、部署或发送消息。
