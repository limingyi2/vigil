# Vigil 插件系统与 Creator 优化方案

日期：2026-10-15（Asia/Shanghai）
代码基线：`4c541ac`，Vigil v1.0.1
状态：开发方案，尚未实施；涉及新协议、权限与默认限额的内容均为设计要求。

2026-10-15 范围更新：主对话与 Creator 的共同执行策略见 [多步任务执行优化方案](VIGIL_AGENT_EXECUTION_OPTIMIZATION_PLAN.md)。该方案扩展本文件原先只优化 Creator 的范围；生命周期、模型能力与未知上限策略以共同方案及后续 P0 契约修订为准。本文件继续保留插件结构、隔离、授权和安装方面的细节。

## 1. 工作线与范围

本轮优先优化 Vigil 自身的插件生成、预览、授权和安装体验。

- 暂停原生任务恢复工作线；保留 `VIGIL_TASK_RECOVERY_STAGE1.md` 原文件，不继续修订或实施其阶段二。
- Creator 保留主页聊天 composer 入口，不另建一套聊天产品。
- 先改善生成链路，再扩展文件结构和运行能力；每阶段单独验收。
- 不开发 GitHub 项目可视化插件，不实现分支图、项目进度识别、仓库导入或同步业务。
- 不扩展 Codex 接管；普通聊天执行优化按共同方案推进，保留既有模型配置和已有内置插件兼容性。

本轮目标：能生成带前端的多文件插件；生成过程可见；联网和文件访问通过可执行的授权边界管理；取消固定 4096 tokens 上限，支持受预算约束的分文件生成和有限修复。

## 2. 已核对的现状与问题

| 环节 | v1.0.1 当前行为 | 优化方向 |
|---|---|---|
| 普通聊天 | 已有 SSE/IPC 流和 `think`、`text`、`done` 展示 | 提取可复用的流式展示组件与订阅机制 |
| Creator | `/api/creator/draft` 调用非流式 `provider.chat()` | 生成作业与显示订阅分开，展示实际进度 |
| 输出 | 一个 JSON 对象内携带所有文件源码 | 小型结构计划 + 逐文件内容生成 + 最终组装 |
| 输出预算 | `max_tokens=4096`、单次超时 180 秒 | 删除固定值，采用模型配置与作业预算 |
| 错误 | 主要读取 `message.content`，未细分结束原因 | 区分空正文、截断、格式、服务和验证错误 |
| 文件 | Creator 插件只接受 `.py/.json/.md/.txt`；结构检查拒绝子目录 | 版本化多文件契约，生成器、检查器、安装器、宿主同步适配 |
| 联网等要求 | 主要由提示词要求禁止 | 改为能力声明、管理员授权及宿主实际检查 |
| 安装 | 已有版本/字节摘要绑定、一次性审批和事务安装 | 扩展绑定权限声明及授权，继续复用事务入口 |

现有静态检查不执行生成代码，也不是安全沙箱。当前进程内 Python 插件与已有前端注入机制不能仅凭新增 Manifest 字段，就宣称具备逐目录或逐域名限制。

截图中的空正文报错只能定位错误分支；真实原因是否为 token 耗尽、提供者行为或其他响应问题，须以结束原因和受控诊断确认，不能直接归咎于模型。

## 3. 哪些限制调整，哪些继续保留

| 项目 | 本轮处理 |
|---|---|
| 固定 4096 tokens | 删除统一硬编码；已知能力时适配，未知且接口允许时省略，必须传值时使用明确标记的可配置兼容值；均检查截断及预算 |
| 只能生成小型单文件插件 | 支持规划文件结构、逐文件生成及受控子目录 |
| 前端文件禁止 | 新契约支持 `.html/.js/.css`，静态资源类型单独列白名单 |
| 提示词全面禁止联网 | 改为要求声明用途、目标和能力；实际使用仍须宿主授权 |
| 提示词全面禁止目录外访问 | 改为限定在用户授权的目录范围内访问 |
| 无界生成或修复 | 保留作业总预算、文件大小/数量和修复次数上限 |
| 自动安装依赖 | 本轮继续禁止；需要依赖时生成声明与说明，由后续流程单独处理 |
| 路径穿越、越权访问、自动安装 | 继续阻止；生成草稿不获得运行或安装权限 |

各文件数量、总字节数和目录深度的初始上限须在 P0 确定并集中配置，界面显示实际限制；不在多个模块各自硬编码。

## 4. 目标生成流程

```text
用户发送创作需求
  → 创建 Creator 作业并返回 job_id
  → 生成文件计划、接口和能力声明
  → 校验计划与文件路径
  → 按依赖顺序逐文件生成
  → 文件语法、包结构、引用与能力检查
  → 对可修正失败进行有限修复
  → 组装正式草稿及验证报告
  → 用户审核文件、差异和所需权限
  → 明确批准后安装
```

生成过程中不执行插件，不测试真实联网，不使用生产凭据，不自动调用 pip/npm。

### 4.1 Creator 作业与流式事件

建议协议形态，P0 冻结具体字段与兼容方式：

- `POST /api/creator/jobs`：创建作业；稳定 `request_id` 防止提交重发创建重复作业。
- `GET /api/creator/jobs/<id>`：读取状态、文件清单、验证结果和可用事件游标。
- `GET /api/creator/jobs/<id>/events?after=<seq>`：只读订阅或补读已有事件；不得启动新的模型生成。
- `POST /api/creator/jobs/<id>/cancel`：请求取消，停止继续派发后续模型请求。
- 旧 `/api/creator/draft`、`/api/creator/revise` 保留兼容，避免破坏现有调用者；具体包装方式由 P0 固定。

作业至少包含归属、请求 ID、当前阶段、状态、模型快照、预算/消耗、文件状态和安全错误分类。读取、订阅、取消均校验归属及既有认证，`job_id` 本身不是授权。

事件使用 `job_id + seq` 标识，建议种类：

| 事件 | 内容 |
|---|---|
| `stage` | 分析、规划、生成文件、验证、修复等真实阶段 |
| `think_delta` | 模型实际返回且可展示的思考内容；未提供时不伪造 |
| `text_delta` | 可见说明或当前文件的生成预览 |
| `file_started/file_completed` | 文件名、状态、长度和检查结果 |
| `validation` | 静态检查问题及当前处理结果 |
| `usage` | 已知的消耗与剩余预算；未知费用不显示虚构数值 |
| `done/error/cancelled` | 明确终态，避免无终止的等待提示 |

正文、思考区和错误样式复用主对话；控制逻辑按 `job_id` 隔离，不能串入普通聊天或另一个生成作业。

订阅通过现有 Electron preload/main 代理接入，不让渲染器直接取得 Brain Token。断开显示连接不代表取消；重新订阅不会重发生成请求。缓存缺口通过快照恢复并明确提示，不能声称补回已丢弃的逐 token 事件。

完整思考内容只作临时展示，不写入插件文件、长期日志或恢复检查点。文件预览均以文本展示，不能作为 HTML 注入聊天页。

本轮只做 Creator 必需的作业状态和已有文件保存，不实施暂停中的原生 Task/Step/Attempt 恢复系统。Brain 重启后未完成作业标为中断；不承诺跨重启自动续跑，也不自动重新计费生成。

### 4.2 错误、截断与有限修复

- 保留提供者结束原因，至少区分 `empty_content`、`output_truncated`、`invalid_format`、`provider_error`、`validation_failed`、`budget_exhausted`。
- 思考内容不能代替源码正文；只返回思考时提示“未得到文件正文”。
- 结构计划可使用已确认支持的 JSON/schema 输出能力；不向所有服务商盲目发送同一格式参数。
- 逐文件生成以服务端已批准的文件名为目标，内容协议与模型身份分开，减少巨大 JSON 中源码转义导致的失败。
- 截断后不得把半个文件标为完成。仅在预算允许时继续该文件或重新生成该文件，再整体检查。
- 格式修复和语法修复有分别计数的上限；建议初版每文件一次自动修复。P0 固定每文件及整作业上限。
- 错误展示安全分类、受影响文件和操作建议；诊断不得直接打印完整模型响应、请求头或凭据。

## 5. 多文件插件契约

建议新增包格式版本，例如：

```text
sample-panel/
├── zxplugin.json
├── __init__.py
├── frontend/
│   ├── index.html
│   ├── app.js
│   └── style.css
└── README.md
```

这是目标结构示意，不表示现有宿主已经支持。受限模式不启用任意 Python 后端；后端执行须满足第 6 节条件。

Manifest 明确包格式版本、插件 ID、入口、前端资源、能力声明、依赖声明和最低宿主版本。工具说明、函数签名和 schema 必须与真实宿主一致，生成器不能自行创造不存在的 API。

实施时同时修改：

1. Creator 输出计划与模板。
2. 文件名、扩展名、目录和大小校验。
3. `plugin_structure` 对多文件结构、入口和资源引用的检查。
4. 安装、更新、回滚对相同结构的支持。
5. 前端资源加载器与宿主通信接口。

保持旧单文件格式兼容；新格式要有明确版本，不把新目录结构误当成旧格式静默安装。

验证包括 Python 语法、JS 语法、Manifest、入口存在性、相对资源引用和能力字段。不执行生成代码来完成静态验证；格式通过不代表业务正确。

## 6. 能力声明与授权

### 6.1 首批能力

| 能力 | 授权范围 | 宿主执行方式 |
|---|---|---|
| `storage.plugin` | 本插件专属数据目录 | 由宿主解析插件身份并限定目录 |
| `filesystem.read` | 用户选定目录及读取范围 | 宿主校验路径、符号链接和当前授权 |
| `filesystem.write` | 明确批准的输出目录或目标 | 宿主检查当前权限及写入策略 |
| `network.https` | 目标域名、用途及允许的方法 | 宿主代发请求，限制跳转和目标地址 |
| `background.sync` | 频率、用途、启停状态 | 宿主调度，撤销后停止新任务 |

未知能力默认拒绝。声明、授予、运行时检查分别记录，Manifest 不能自授权限。

第三方账号接入只预留通用凭据引用机制，本轮不建设 GitHub 连接器或任何仓库业务。令牌由宿主管理，插件只得到经过授权的操作结果，不得到凭据值。

### 6.2 实际执行边界

- 新生成的前端运行在隔离容器中，不共享主聊天 DOM，不直接获得 `window.vigil`、Node、Electron 或 Brain Token。
- 前端调用受控宿主桥；桥按实际插件身份、已批准版本和当前授权检查每一次调用，不能只相信消息中的插件 ID。
- 前端默认阻止直接外连，通过宿主网络代理申请访问。代理校验域名、方法、目标 IP、重定向与返回大小；跳转不能绕过授权或带出凭据。
- 独立 Python 进程只能提供故障隔离，本身不能限制文件和网络能力。任意 Python 后端只有在可验证的权限隔离完成后，才能作为“受限插件”启用。
- 可先交付“隔离前端 + 声明式宿主动作”的受限模式。尚未实现的 Python 隔离能力明确标为不支持；保持草稿可审核，不自动降级为全权限运行。
- 已有原生受信插件保持兼容，其权限边界如实标注。不得给它们加一个 Manifest 就宣称已经受限，也不在本轮自动迁移已有插件。

### 6.3 授权生命周期

安装前展示能力、用途和具体范围；运行时再次核验。更新新增权限、变更授权范围或改变已审核字节后，旧批准失效，需要重新审核。

撤销后拒绝新的能力调用，并停止后续后台调度。已经发出的请求或写入需要报告实际完成情况，不能把撤销等同于回滚所有副作用。

能力授权记录与现有 Creator 一次性安装批准分开，批准快照同时绑定代码摘要、Manifest 和权限要求。安装继续委托现有事务实现，不增加旁路复制安装器。

## 7. 生成预算重构

### 7.1 用户要求与实施原则

移除 Creator 固定的 `max_tokens=4096`。普通用户不必为每次生成手动填写 tokens；高级设置可以覆盖模型输出预算。

不承诺无限输出。直接省略 `max_tokens` 可能触发服务商默认小上限，因此须按实际模型/提供者能力决定请求参数；能力未知时采用有说明的兼容配置，不猜测最大值。

### 7.2 分层预算

| 层级 | 作用 |
|---|---|
| 单次模型请求 | 适配模型上下文和可用输出上限；结合当前文件任务分配 |
| 单个文件 | 限定总字节、续写/重生成及自动修复次数 |
| 整个作业 | 限定总请求、累计 tokens、时间和可确认的费用 |

请求、修复、继续生成都计入同一个作业消耗。显示连接重连不增加生成请求。

预算耗尽后停止新请求，保留已验证文件与错误位置；用户明确继续时授予额外预算，累计消耗保留。费用无法准确计算时显示“未知”，仍用请求数、tokens、字节和时长约束。

模型与服务商配置在作业创建时固定快照，用户在聊天中切换模型不能悄悄改变正在生成的作业；重新选模型属于明确的新操作，不复制凭据进作业记录。

## 8. 分阶段实施与验收

| 阶段 | 实施内容 | 验收门槛 |
|---|---|---|
| P0 契约与兼容设计 | 冻结包格式、事件协议、错误分类、模型预算配置、能力边界和默认资源上限 | 样例、状态、字段和兼容路线无冲突；明确受限模式实际可执行范围 |
| P1 生成可靠性与流式 | 作业状态、现有流式 UI 复用、结束原因、移除 4096 硬编码、取消与错误处理 | 实际流按作业隔离；空正文/截断可区分；重连不重复生成；普通聊天回归通过 |
| P2 多文件草稿 | 文件计划、逐文件生成、受控目录、检查器和差异展示 | 多文件草稿可读可审；半文件不得进入正式可安装状态；旧格式仍有效 |
| P3 宿主能力与隔离 | 隔离前端、能力桥、授权记录、网络/目录检查及撤销 | 未授权访问被实际阻止；无法提供的隔离能力保持不支持 |
| P4 安装更新衔接 | 绑定文件和能力的审批快照、事务安装、更新和回滚 | 新权限触发重审；旧批准/重复消费失败；安装失败保持既有版本 |
| P5 专项验收与发布 | 构建、干净环境安装和回归；更新使用与权限说明 | 源码、客户端、随包 Brain 与产物版本一致，形成发布证据 |

P1/P2 阶段即使生成了联网调用代码，也不能提前安装为受限运行插件；权限执行边界须在 P3 验收完成。

## 9. 针对性测试

优先使用临时 VIGIL_HOME、本地模型流夹具和无害插件，不读取生产凭据，不用真实外部账号进行自动测试。

1. 流事件：正文、可选思考、错误、终态；按 job_id 隔离；重复事件与游标缺口；重连不重发模型请求。
2. 生成错误：空正文、仅思考、截断、非法 JSON、服务错误、取消、预算耗尽和修复失败。
3. 文件：路径逃逸、非法扩展名、大小/数量上限、资源缺失、源码语法、部分生成失败和旧格式兼容。
4. 权限：未声明、未授予、错误插件身份、范围外目录、未授权域名、重定向绕过及撤销后调用。
5. 前端：生成文本不执行；插件容器无法读取主界面 bridge/DOM/凭据；受控桥只允许已授权操作。
6. 安装：草稿修改使审批失效、权限扩大重审、并发一次消费、失败回滚和正确的重启提示。
7. 桌面：主聊天流式、Creator 草稿卡、取消、模型切换、历史回看和已有内置插件针对性回归。

原生 Python 权限隔离须单独提供可复验的失败用例；只证明进程能启动不能通过该项验收。

## 10. 最终交付与发布条件

- 可生成并审核带前端的多文件插件草稿。
- Creator 有真实流式过程、清晰错误及取消入口。
- 固定 4096 tokens 硬编码移除，模型适配与作业预算可配置、可解释。
- 已开放能力具备可验证的宿主授权与撤销；尚不支持的能力明确拒绝。
- 代码/权限变化使旧安装批准失效，既有事务与回滚机制保留。
- 新旧插件格式、普通聊天与内置插件均通过针对性验证。
- 使用通用的无害信息面板及受控测试服务验收，不以 GitHub 可视化插件作为交付物。

每阶段代码和验收记录单独提交；版本号在发布阶段确定。本文档不代表任何新能力已经实现，不触发打包、安装或发布。
