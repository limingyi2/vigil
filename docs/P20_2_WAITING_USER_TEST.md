## 环境准备

1. 可用的 Python 3.12 + 仓库依赖（`pip install -r brain/requirements.txt`，
   参照 `.github/workflows/tests.yml` 的 unittest job）。
2. 启动 Brain：`cd brain && python server.py`（或打包版 sidecar）。
3. 启动客户端：`cd client && npm start`。
4. 准备一个**可安全破坏的测试插件**：在插件面板安装一个自建的 minimal
   插件（含 manifest.json），**不要用 Wallpaper 或任何真实重要插件**。

## 场景 1：禁用已安装的测试插件（主链路）

1. 对 Vigil 说："帮我禁用 `<测试插件名>` 插件。"
2. 预期：Agent Run 出现"等待你的授权"步骤卡片（默认展开），显示操作
   （plugins_skills.disable）、目标（插件名）与实际参数；**未批准前插件状态
   不变化**，卡片上插件仍为启用状态。
3. 点击"确认执行"：卡片变为"已确认并执行成功"，并显示真实回执
   （含 after 状态复核 enabled=false）；到插件面板核实插件确实已禁用。

## 场景 2：拒绝

1. 重新发起同一请求（此时会产生新的待审批请求）。
2. 点击"拒绝"：卡片显示"已拒绝，未执行"；插件面板核实插件保持原状。

## 场景 3：重复确认

1. 再次发起禁用请求，快速双击"确认执行"（或在另一个窗口同时打开同一
   会话后各点一次）。
2. 预期：只有一次实际禁用生效；第二次点击显示"正在执行…（另一个确认
   已受理）"或已完成结果，插件面板核实无异常、无重复副作用报错。

## 场景 4：历史卡片与 Brain 重启

1. 在有已批准/已拒绝卡片的会话里重启 Brain（重启后内存审批请求丢失）。
2. 重新打开该会话：历史卡片显示"审批已失效，请重新发起"，**没有可点的
   确认按钮**。
3. 重新发起同一操作可获得新的审批卡片，正常走完场景 1。

## 场景 5：切换会话与客户端重启

1. 完成一次批准后切换到其他会话再切回：卡片状态仍与 Brain 一致
   （completed 显示真实结果，pending 仍可操作）。
2. 完全关闭并重启客户端（Brain 不重启）：历史卡片状态不变。

## 场景 6：只读能力不弹审批
