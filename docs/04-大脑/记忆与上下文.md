# 记忆与上下文改造说明

> 这份文档记录记忆系统的三处改造：约定到点提醒、冲突优先级、历史摘要。
> **举例一律用泛化说法** —— 真实记忆内容不进仓库。

---

## 一句话总览

| | 改动前 | 改动后 |
|---|---|---|
| 她怎么记住事 | 只有最近 **6 个来回**的原话，超出的**直接丢掉**（不变成任何东西） | 旧对话压成日/周/月摘要跟着走；**有日期的约定按时间强制带上** |
| 跨天的事 | 聊完就散，"前天聊的今天就忘" | 能接上几天前的话题；约定临近会自己想起来 |
| 过期的约定 | 过期即消失 → 她把已发生的事当成还没到 | 保留并标清"已经过完的日子" |
| 记忆库质量 | 混着模型幻觉与旧人设残留 | 按类型清掉，只剩真实信息 |

---

## 一、约定到点提醒 —— 新建 `brain/agenda.py`

**要解决的问题**：用户说"我让她假期来找我玩"，这事会被记进记忆库；但之后用户说"快到了、终于要快见到了"，她**不一定想得起来**。

因为记忆库是"语义命中才带"的。实测（拿真实记忆库复现）：

| 用户的实际说法 | 那条约定排第几名 | 结果 |
|---|---|---|
| 假期和调休是不是连着放 | 第 2 名 | 能召回 |
| 放假第一天还要上班（真说过） | 第 13 名 | **召不回**（只取前 5） |
| 一句三五个字的短问句 | — | **压根不检索** |

**同一件事，换个说法就漏。**

**改法**：约定跟别的记忆不是一类东西 —— **它是有时效的**。有日期就不该靠语义碰运气，应该按时间窗口无条件带上。于是：

1. 扫记忆库的 event，用白名单正则解析日期（`X月Y日` / `Y号` / `明天后天` / `下周X` / `法定假日` / `周末` / `月底` / ISO 日期）
2. **解析不出来的不写进账本**（宁可漏，不可错）
3. 注入时按日期分两段呈现：

```
【日程】今天是 9月29日（周二）。他提过的事都在下面，别装不知道。分两段看：
"还没到的"是往后要办的；"已经过完的日子"是指那天已经过去了 ——
提它要用"那次""当时"这种过去说法，别"到时候见"、别当成还没到。
还没到的：
· 10月1日（2 天后）：<某条还没到的约定>
已经过完的日子（别再当约好的事提）：
· 9月25日（4 天前）：<某条已经过完的约定>
```

**关键细节**：
- 放在**生活块之后**是故意的 —— 冲突时它离输出更近，才能压过"我们那边不放那么多假"这类日常设定
- 「今天是 X月X日」必须写在块里，不能只靠 system 最前面那句时间提示（隔了 4000 多字，注意力早散了）

## 二、冲突优先级 —— `persona_store.py`

原来的毛病：记忆里有一件约好的事，可她的生活块（世界设定）写着另一套 —— 用户问起时，她答的是**生活块那句**，记忆一个字没提。因为生活块离输出更近，两套事实打架时没有任何优先级规则。

**改法**：在说话规则里加一条，并且放在"异地"那句**前面**（权重更高）：

> 重要：【日程】里列的是你们说定的安排，别否认、别装不知道。它比你生活里的日常设定优先 —— 万一打架，按约好的来，别拿设定去顶他说过的事

顺手给"异地"那条加了豁免（"已约好的具体安排除外"）—— 否则它和这条互相绊住：一边说"别说我明天去看你"，一边说"按约好的来"。

## 三、历史摘要（recap）—— `recap_store.py`

**以前的机制是丢弃式的**：内存只留 24 条、每轮只注入 12 条，超出的从头部**硬丢**且**不变成任何东西**；磁盘上的聊天存档永久留着，但**从不读回**（只有重启时灌最后 16 条）。

实测一份真实存档：**530 条 / 12,680 字 / 跨 10 天**，聊天时她一条都看不见。

**改法**：三层，总量封顶 1500 字，不随天数增长（这就是必须分层的原因 —— 只做日摘要的话，90 天就是 10,800 字，跟固定骨架一样沉）：

```
最近 7 天   → 日摘要    data/summary/YYYY-MM-DD.md
8 ~ 30 天   → 周摘要    data/summary/rollup/YYYY-Www.md
30 天以上   → 月摘要    data/summary/rollup/YYYY-MM.md
```

**这轮修掉的两个真 bug**（都是回放真实存档时暴露的）：

1. **`LOOP_MAX` 常量从未定义** —— `py_compile` 查不出来（函数体内、运行时才求值），一调 `tick()` 就 NameError，会被异常处理吞成"摘要功能静默失效"。
2. **日→周升级后不删源文件** → ① 同一天既在日摘要里又在周摘要里，注入块白白多出 170 字重复；② 更隐蔽的：跨周时某天可能是**后来才变老**的，它进不了那个已生成的周文件，又会因为"有周文件"被跳过 —— **两边都不在，直接丢内容**。

修完用真实存档回放：注入块 923 → 802 字，无重复、无丢失，原始存档一条未动。

## 四、记忆库清理：按类型而非按条数

抽错的记忆有固定的几种类型（**举例已泛化**）：

| 类型 | 特征 | 为什么是错的 |
|---|---|---|
| 模型幻觉 | 从"出游订房"推成"同居结婚" | 模型补全了用户没说的关系 |
| 模糊推断 | "不愿让对方住条件差的旅馆（**可能涉及**…）" | 带"可能"的推断被当成事实存下来 |
| 旧人设残留 | 早期测试时要求的口癖（"回复带某个语气词"） | 新人设明确禁掉，翻出来就会崩 |
| 验证污染 | **开发者自己验证时说的话术被抽成了记忆** | 测试污染，比用户说过的话更容易被当真 |

**真实私人信息（作息、感情、行程、舍友、喜好）默认全部保留**，删不删由用户自己定。

技术上有两点必须记住：**删条目要走 `MemoryStore.delete()`**（它会同步更新向量索引，直接改 json 会留下 orphan 占检索名额）；**删完必须重启服务**（`MemoryStore` 实例常驻在服务进程内存里）。

## 五、云端真机验收

md5 六个文件全部与本地**逐字节一致**，配置未被覆盖（api_key 位数、vision 与 chat 模型名逐项核对）。

验收看的是**行为**而不是具体内容 —— 四条，各验一个方向：

```
<问一个还没到的约会>       → 答得出，且给的是"往前"的说法
<问之前说好过什么事>       → 能列出来，不会装不知道
<明确问过去某天做了什么>   → 用过去时回答，不当成还没到
<要看她的日记>             → 挡回来，边界没坏
```

延迟 1.6 ~ 2.9 秒，**没有上升**——摘要和日程都是纯文本注入，不产生额外请求。
（对比：如果做成"工具调用"那一套，每次要多一次 API 往返，延迟直接翻倍。）

## 七、已知局限（说清楚，别踩）

1. **摘要记的是"聊过什么话题"，不是逐句原话。** 指望她复述细节会失望；"上周你提过某件事"这种程度是准的。
2. **摘要由模型生成，模型会编。** 防护是三重：压缩 prompt 明令只写确实出现过的、原始存档一条不删（随时能重压）、API 挂了降级成截断拼接。回放时确实看到过一处人名错字。
3. **用户主动制造未来语境时（"快到了、终于要快见到了"），她仍可能顺着接成未来的安排。** 因为**是用户自己造了那个语境**，中文本身没有时态标记。但明确问过去她回答正确。这算合理极限。
4. **日程只认白名单里的日期说法**。"过两天""下周有空的时候"这类模糊表达解析不出来，不会进账本（宁可漏不可错）。
