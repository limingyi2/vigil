# 上下文与长期记忆

当前桌面版使用会话历史、上下文压缩、历史检索和长期记忆共同构造模型输入。它们有不同的数据范围和恢复方式。

## 会话上下文

`brain/conversation_context.py` 负责组织当前会话的模型输入，`brain/history_retrieval.py` 提供历史证据。近期消息、压缩状态和历史检索按人设、来源与 `conversation_id` 隔离。

上下文超过预算时，会压缩当前会话较早的消息。原始聊天 JSONL 保留，摘要用于控制后续请求的上下文大小，不能代替原始记录。

没有明确会话的内部调用使用相应的默认上下文，不能沿用上一次请求的会话 ID。会话切换与请求结束时还需要维护附件引用、显示记录和任务回执的一致性。

## 长期记忆

`brain/memory_store_v2.py` 管理长期记忆。当前默认仓库为配置记忆目录下的 `memory.json`，`memory_dir` 可指定目录。传入的人设与来源参数保留兼容签名，不再用于选择新的记忆文件。

主仓库不存在且旧 `pc.memory.json` 存在时，现有迁移逻辑会将该文件移到主仓库。其余历史分区可能保留，界面允许查看残留文件。不要把不同分区简单拼接，也不要在程序运行时手动改名或删除文件。

记忆星图读取记忆与关系，用于浏览。装饰星点不计入记忆数量；独立演示页使用的样例或本地哈希向量不等于真实嵌入结果。

## 知识库与检索

知识库文档通过统一 SQLite 存储维护。聊天历史、记忆、知识库和授权工作区资料使用检索范围过滤，不能因共享检索入口而放宽可访问范围。

关键词和向量结果使用 RRF 融合。知识库展示分数做了归一化，用于现有的 0–1 门槛；它是排序指标，不是“模型回答正确的概率”。算法和参数见 [混合检索说明](../RAG混合检索系统设计与优化.md)。

## 旧格式

`conversation_context` 的 `legacy_summary` 只用于对应会话状态中的旧字段兼容。旧 `recap_store` 已退出运行路径，历史 `data/summary/` 文件不会因此自动导入、合并或删除。

早期约定账本、主动消息与陪伴功能的设计保留在历史资料中，不作为当前桌面工作台的功能说明。维护旧数据前应先备份并确认来源，例子和问题反馈中不要包含真实记忆或会话原文。
