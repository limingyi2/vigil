# 统一管理功能 — 合并方案与使用说明

## 一、功能概述

统一管理让你在一个页面里监控所有运行 Vigil 大脑的实例（云端服务器 A、云端服务器 B、本地电脑等），实时查看每个节点的在线状态、CPU/内存/磁盘占用、最后心跳时间。

## 二、架构

```
┌─────────────────┐     心跳(15s/次)      ┌─────────────────┐
│  云端服务器 B    │ ─────────────────────► │                 │
│  management_    │                        │  云端服务器 A    │
│  agent.py       │                        │  (管理中心)      │
└─────────────────┘                        │  brain +        │
                                           │  management.py  │
┌─────────────────┐                        │                 │
│  本地电脑        │ ─────────────────────► │  /api/management│
│  management_    │                        │  /overview      │
│  agent.py       │                        └────────┬────────┘
└─────────────────┘                                 │
                                                    │ HTTP
                                                    ▼
                                          ┌─────────────────┐
                                          │   客户端         │
                                          │  「统一管理」页  │
                                          └─────────────────┘
```

## 三、后端（已完成）

### 3.1 管理中心（云端服务器 A）

文件：`brain/management.py`

- 接收心跳：`POST /api/management/heartbeat`
- 查询概览：`GET /api/management/overview`
- 查询服务器：`GET /api/management/servers`
- 查询 Agent：`GET /api/management/agents`
- 查询日志：`GET /api/management/agents/{node_id}/logs`

状态判断：
- **在线**：最后心跳 ≤ 45 秒
- **延迟**：最后心跳 ≤ 90 秒
- **离线**：最后心跳 > 90 秒

### 3.2 监控 Agent（被管理节点）

文件：`brain/management_agent.py`

每 15 秒向管理中心上报：
- node_id、name、hostname、platform
- metrics：cpu_percent、memory_percent、disk_percent
- agents：该节点运行的 Agent 列表
- logs：最近日志

## 四、客户端（已完成）

文件：`client/src/js/pages.js` — `renderManagement` 函数

页面包含三个子页：

### 4.1 节点概览
- 顶部 KPI：总节点 / 在线 / 延迟 / 离线
- 节点卡片列表：每个节点显示
  - 名称、ID、主机名、平台
  - 状态标签（绿色在线 / 黄色延迟 / 红色离线）
  - CPU / 内存 / 磁盘 进度条（>85% 红色，>65% 黄色）
  - 最后心跳时间（相对时间）
  - 运行中的 Agent 数量
- 每 15 秒自动刷新

### 4.2 Agent 列表
- 表格展示所有节点上报的 Agent
- 列：Agent 名称、所属节点、状态、详情

### 4.3 配置说明
- 内置 3 步接入教程

## 五、部署配置

### 5.1 管理中心（云端服务器 A）

在启动 brain 的环境变量里配置令牌：

```batch
:: Windows
set VIGIL_MANAGEMENT_AGENT_TOKENS={"server-b":"你的随机长令牌A","local-pc":"你的随机长令牌B"}
set VIGIL_MANAGEMENT_AGENT_NAMES={"server-b":"云端服务器 B","local-pc":"本地电脑"}
```

```bash
# Linux
export VIGIL_MANAGEMENT_AGENT_TOKENS='{"server-b":"你的随机长令牌A","local-pc":"你的随机长令牌B"}'
export VIGIL_MANAGEMENT_AGENT_NAMES='{"server-b":"云端服务器 B","local-pc":"本地电脑"}'
```

> 令牌建议用 `openssl rand -hex 32` 生成。

### 5.2 被管理节点（云端服务器 B / 本地电脑）

```batch
:: Windows
set VIGIL_MANAGEMENT_URL=http://管理中心公网IP:8788
set VIGIL_MANAGEMENT_NODE_ID=server-b
set VIGIL_MANAGEMENT_TOKEN=你的随机长令牌A
set VIGIL_MANAGEMENT_NAME=云端服务器 B
python brain/management_agent.py
```

```bash
# Linux
export VIGIL_MANAGEMENT_URL=http://管理中心公网IP:8788
export VIGIL_MANAGEMENT_NODE_ID=server-b
export VIGIL_MANAGEMENT_TOKEN=你的随机长令牌A
export VIGIL_MANAGEMENT_NAME=云端服务器 B
python brain/management_agent.py
```

### 5.3 设为开机自启（可选）

**Windows**：创建 `.bat` 启动脚本，放入 `shell:startup` 文件夹。

**Linux**：创建 systemd service。

## 七、接入你的两个云服务器

### 服务器 A（阿里云杭州，管理中心）
1. 在启动 brain 的脚本里加 `VIGIL_MANAGEMENT_AGENT_TOKENS` 环境变量
2. 重启 brain

### 服务器 B（腾讯北京，微信桥接）
1. 把 `brain/management_agent.py` 传到服务器 B
2. 配置环境变量（指向服务器 A 的公网地址）
3. 后台运行 Agent（建议用 pm2 或 systemd）

### 本地电脑
1. 配置环境变量（指向服务器 A）
2. 运行 `python brain/management_agent.py`
3. （可选）设为开机自启

## 八、安全说明

- Agent 令牌只从环境变量读取，不写入 management.json
- 心跳接口用 HMAC 常量时间比较，防时序攻击
- 管理 API（overview/servers/agents）走大脑原有鉴权
- 心跳接口绕过通用鉴权，用独立 Agent 令牌
